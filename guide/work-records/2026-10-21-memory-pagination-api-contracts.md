# 2026-10-21 기억 분할 로딩과 API 계약 검사

후속 상태: 이 기록은 당시 범위다. 이후 사용자가 전체 API 문서화와 UI 구조
구현을 요청해, 60개 미문서화 예외를 제거하고 구조를 분리했다.

작업 ID: Task: none (사용자 요청: 목록 분할 로딩·API 계약 검증 구현, UI 구조는 설명만)

## 이유와 변경

기억 목록은 시작·검토 후 재로딩·주기적 갱신에서 최대 10만 건을 끝까지 읽었다.
첫 요청은 50개만 읽고 기존 ‘더 보기’에서 다음 서버 커서를 요청하게 바꿨다.
동시 요청을 합치고, 연결·scope·검색이 바뀐 뒤 늦게 도착한 결과를 버린다.
실패한 페이지는 기존 목록·커서를 보존한다. 반복 커서·과대 응답·잘못된 ID와
authority를 거부한다. 주기적 갱신은 읽은 페이지 창만 원자적으로 재검증한다.
실패한 갱신의 재시도도 그 창을 다시 읽으며, 새 페이지를 덧붙이지 않는다.

활성 목록의 검색·종류 필터는 전체 서버 목록을 대상으로 한다. 새 선택적
`ignore_case=true`는 본문·요약을 대소문자 구분 없이 찾는다. 기존 기본 검색은
본문의 대소문자 구분 검색으로 유지한다. 커서는 검색 방식에도 결합한다.
구버전 서버가 새 인자를 거부하면 실제 성공을 확인한 뒤 기존 본문 검색으로
돌아가며 그 차이를 표시한다. 미로딩 기억도 검색 결과에서 상세를 열 수 있다.

개수·저장소 선택·로컬 정렬은 불러온 목록 기준임을 표시한다. provenance/idle
화면의 검색도 해당 범위임을 별도로 표시한다. 사용률을 일부 목록에서 전체
수치로 계산하지 않는다. 주기적 사용량 재조회는 유지한다. 정리 제안의 대상
기억은 별도로 최대 네 요청씩 확인해 첫 페이지 밖이라는 이유로 제안을 잃지
않게 했다. 접근 실패한 대상은 숨기며 전체 목록 로딩은 실패시키지 않는다.

공식 OpenAPI 3.1 구조 스키마를 원본 SHA256·출처·라이선스와 함께 고정했다.
검사는 네트워크 없이 문서 구조·내부 참조·내장 JSON Schema·경로 변수 계약을
검사한다. 실제 Windows Go 핸들러의 정상·오류 응답도 문서와 대조한다.
검사 중 발견한 끊어진 `CodeReviews` 참조, 필수 경로 변수 10곳을 고쳤다.
관리 API 다섯 개가 잘못 들어 있던 gateway 확장에서 실제 `paths`로 옮기고
관리 API의 공개 루트 응답도 명시했다. 큰 문서 diff 일부는 이 다섯 항목의
이동이며 임의 전체 재포맷은 하지 않았다.

**기존 미문서화 관리 API 60개는 여전히 계약이 없다.** 허술한 빈 스키마로
덮지 않고 `api/legacy-undocumented-routes.json`에 기록한다. 새 누락·삭제된
경로의 낡은 예외·이미 문서화된 경로의 남은 예외는 CI를 실패시킨다. 이 목록을
통과한 계약 수에 포함하지 않는다. 정적 구조 검사는 211개 문서화 operation,
실제 응답 스키마 검사는 현재 기억 목록에 한정한다.

UI의 대규모 구조 재편은 실행하지 않았다. 기존 화면에 분할 로딩을 연결하는
작은 전송 도우미만 추가했다. app.js/crew.js의 기능 분리, 상태의 소유권,
ES modules·번들 조립, 번역 지연 로딩 권고는 별도 구조 개선안에만 썼다.

## 실행한 검증

- 실제 Windows `go test -count=1 -v -run '^TestMemoryList|^TestHTTPRoutes|^TestOpenAPI'`
  대상 최상위 검사 9개와 하위 사례 통과, skip 0개. 실제 핸들러 응답 10개를
  수집해 로컬 JSON Schema 검사를 모두 통과했다. 조건 변경 커서 거부,
  기본 검색 보존, 요약·대소문자 검색, 잘못된 인자와 익명 거부를 포함한다.
- 문서 211개 operation 구조·내부 참조·경로 변수 검사 통과. 검증기 자체의
  회귀 4개 통과: 깨진 참조, 빠진 경로 변수, 잘못된 응답 authority/속성/타입을
  실제로 거부함을 확인했다. 기존 60개 미문서화 경로는 별도 부채다.
- 커서 전송 도우미 단위 검사 6개 통과. 기존 UI를 포함한 테스트 파일
  14개 통과, 영문 정적 문자열·템플릿 누락 0개.
- 실제 앱 HTML·전체 스크립트·스타일을 Chromium에서 읽고 가짜 native API로
  검증했다. 시작 시 기억 요청 1개·50행, 클릭 전 미리 다음 커서 요청 없음,
  Enter ‘더 보기’와 초점 유지, 실패 후 100행 보존·재시도 후 150행,
  첫 페이지 밖 90,000번째 기억 검색·상세, 서버 종류 필터, 구버전 서버 검색
  호환, 좁은 화면의 범위 안내 표시를 확인했다. pageerror 0개.
  실제 화면도 확인했다. 이는 실제 서버 연결/설치 전체 E2E가 아니다.
- Better Design 로컬 CSS 최종 발견 0개. 처음 폰트 로더 근거가 없는 토큰
  중복 지정 경고는 기존 `.meta` 글꼴 상속을 사용해 없앴다.
- Go 복잡도 게이트, actionlint, JS 구문, diff 검사 통과.

초기 Windows 컴파일이 소스 목록 함수에 잘못 들어간 검색 변경을 잡았다.
그 부분은 원본으로 복원하고 기억 목록 함수에만 적용한 뒤 재실행했다.
처음 API 경로 검사에서 기존 누락과 gateway 중첩 오류가 드러났으며 위에
별도로 기록했다. 초기 브라우저 선택자의 화살표·동일 문구 충돌도 고친 뒤
최종 전체 화면 검사를 재실행했다. 실패한 실행은 통과로 세지 않는다.

Windows에서 검증한 다섯 소스/규격 파일은 로컬 최종 hash와 대조했다.

## 남은 한계

원격 CI와 새 의존성의 새 환경 설치는 실행하지 않았다. 로컬에 설치된 같은
고정 버전으로 검증했으며 CI 설정 구문을 검사했다. 실제 PostgreSQL 검색
통합은 실행하지 않았다. Windows Go 검사에는 가짜 저장소와 실제 HTTP
핸들러를 사용했다. 모든 API의 실제 요청·응답 계약 검증을 완료한 것은 아니다.

현재 더 보기는 서버에서 받은 행을 누적한다. DOM 가상화, 전체 기준 정렬·
정확한 집계·저장소 목록 API, 후보/스킬 목록의 추가 분할은 별도 개선이다.
주기적 usage 집계 경로는 기존 전체 scope 집계를 유지한다. UI 구조 재편은
사용자 요청대로 제안만 했다. 다른 OS 앱 빌드, 실제 설치/삭제·배포·PR 게시,
새 Windows 설치 파일 패키징은 실행하지 않았다.

# RTE-06/07/08 product wiring: step attribution record, read-only export, pilot switch

Task: RTE-06 (#155), RTE-07, RTE-08
Research: routing attribution, analysis and pilot study (RTE-06~08); the lab code stays in the private research folder
Design: With `ARKISM_ROUTING_ATTRIBUTION=1` (default off) the crew runner sends one record per routed step to `POST /v1/routing/attributions`: a runner-made decision id, the decision time, how the pick was made, the chosen model, the capped fallbacks, every attempt (index, model, ok, error code, latency), the stop reason, the group, an optional pilot arm and the origin ids. Model names come from the decide result, which reads the routing config; nothing is hardcoded. The server stores it in jobs as kind `routing_attribution` under an id derived from scope and decision id: the same record again is a no-op, another record under the same id is a conflict. The body refuses unknown fields, so prompt text, output, memory bodies or tokens cannot ride along. `GET /v1/routing/attributions` (read:routing) pages the records in id order as data only; this is the export the offline analysis (RTE-07) reads. `arkism crew route --pilot-arm NAME` labels a step with a pilot arm and is refused unless the flag is on, so the pilot (RTE-08) can target the real runner only behind the same switch. With the flag off, routing, the result and the call reports are unchanged and nothing is sent.
Relation: adapted
Deviation: The analysis reader and the pilot real-runner plan were added to the private lab (analysis.py, pilot.py), not to this repository, because research code stays private; only this record and the product side are public.
Why: RTE-06~08 existed only in the lab. The product needs a way to record what the runner actually did per routed step, a read-only way to export it, and a switch so a pilot can use the real runner, all off by default.
Verified: `go test -race` for internal/host/crew (whole package) and for internal/memory with `-run 'RoutingAttribution|Routing|OpenAPI|HTTPRoute'` passed. internal/host/crew/routing_attribution_test.go covers flag off (no record, same result and call reports as on), flag on (one record per step with the expected fields and no task or output text, a new decision id per step), a failed send retried once with the same record, and the pilot arm refused without the flag in both runRouted and the CLI. internal/memory/routing_attribution_test.go covers idempotent resend and conflict, 13 malformed records, an extra prompt field refused with 400, paging of the runner-format record and a token without read:routing denied. `TestPostgresRoutingAttributionExport` passed against a disposable Postgres container. tools/check_openapi.py passed, as did go vet, gofmt on the changed files and the complexity gate. In the private lab the new real-runner tests (7) and the existing pilot (83) and analysis (141) tests passed.
Limits: The lab analysis and pilot code are private and not in this change. No real outcome is collected, so the analysis has records but no independent results to join yet. Sending the record is best effort (two tries); a lost record is not retried later and does not fail the step. The export works only on the Postgres store. No real pilot was run and no paid model was called. No build, deploy or merge.

## 한국어 작업 기록

제목: RTE-06~08 제품 연결 — 단계 기록, 읽기 전용 내보내기, 파일럿 스위치
이유: RTE-06~08은 실험실에만 있었다. 제품에서 라우팅 단계마다 실제로 한 일을 남기고, 읽기 전용으로 내보내고, 파일럿이 실제 실행기를 쓸 스위치가 필요했다. 모두 기본은 꺼짐이다.
검증: crew 패키지 전체와 memory 라우팅 관련 시험(-race)이 통과했다. 꺼짐이면 기록 없음·결과 동일, 켜짐이면 단계마다 기록 하나(작업 글·출력 없음), 재전송은 같은 기록, 스위치 없이 파일럿 arm 거부(runRouted·CLI)를 확인했다. memory 쪽은 같은 기록 재전송 무시와 충돌, 잘못된 기록 13건, prompt 필드 400, 실행기 형식 기록의 페이지 읽기, 읽기 권한 없는 토큰 거부를 확인했다. Postgres 시험은 일회용 컨테이너에서 통과했다. OpenAPI 검사, go vet, gofmt, 복잡도 검사가 통과했다. 비공개 실험실의 새 실제 실행기 시험 7개와 기존 pilot 83개·analysis 141개 시험이 통과했다.
한계: 실험실 분석·파일럿 코드는 비공개라 이 변경에 없다. 실제 결과(Outcome)는 아직 모으지 않는다. 기록 전송은 최선 노력(2번)이고 잃어도 단계는 실패하지 않는다. 내보내기는 Postgres 저장소에서만 된다. 실제 파일럿은 돌리지 않았고 유료 모델 호출 없음. 빌드·배포·병합 없음.

# 2026-10-21 principal 토큰 발급·만료·회전

작업 ID: Task: none (공개 평가 P0-3의 토큰 정책)

## 이유와 변경

공통 HTTP 인가만으로 짧거나 영구 유효한 토큰 문제는 해결되지 않는다. 기존
마이그레이션을 수정하지 않고 0003을 추가해 현재 토큰과 회전 이력을 연결했다.
이력에는 SHA-256 다이제스트·principal·발급/만료 시각·이전 다이제스트만 저장한다.
앱 역할은 이력을 읽거나 수정하지 못한다. 복구 쓰기 중지에도 새 테이블을 포함했다.

새 토큰은 32바이트 난수를 base64url 43자 또는 hex 64자로 표현한다. 짧은 값과
서로 다른 바이트가 16개 미만인 반복 입력은 거부한다. 외부 입력의 실제 난수성을
증명하는 검사는 아니므로 비밀번호 해시 대신 OS 난수 생성기를 사용하도록 한다.
`--generate-token-file`은 새 파일에만 쓰고 값을 출력하지 않는다. Unix 0600,
Windows 현재 사용자 SID의 보호 DACL을 파일 생성 시점에 적용한다.

기본/최대 수명은 2160시간, 최소는 1분이다. 기존 토큰은 이관 시점부터 720시간
유예하고 알 수 없는 발급 시각은 null로 둔다. 초기화·권한 추가·재시도로 만료일을
늘리지 않는다. `current_principal`과 모든 권한/RLS 경로가 활성 상태와 발급·만료
시각을 매 SQL 문마다 확인한다. 일광절약시간의 영향을 피하려고 고정 시간을 쓴다.
[PostgreSQL의 시각 함수](https://www.postgresql.org/docs/current/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT)를
확인해 트랜잭션 시작에 고정되는 시각 대신 `statement_timestamp()`를 사용했다.
난수 발급에는 [Go crypto/rand](https://pkg.go.dev/crypto/rand#Read)를 사용한다.

회전은 init 연결과 현재 토큰이 필요한 별도 CLI 작업이다. principal별 잠금과
이전 다이제스트 대조로 동시 교체를 직렬화한다. 교체·이력 기록은 한 트랜잭션이며
즉시 이전 토큰을 거부한다. 회수된 principal은 회전으로 되살리지 않는다. 이력에
남은 토큰 재사용을 거부하며, 같은 이전/새 토큰 쌍의 완료 재시도는 허용한다.

데스크톱 기동 시 관리 중인 owner/worker의 상태를 조회한다. 교체 예정 키를 먼저
개인 설정에 저장하고, 소비 프로세스를 중단한 뒤 DB를 교체하고 완료를 기록한다.
DB 교체 전후의 프로세스 종료는 같은 쌍의 재시도로 복구한다. 백업 형식 2는 현재
토큰과 교체 예정 상태를 함께 보관하며, 형식 1 복원도 유지한다. 이전 앱은 새
형식을 거부해 복구할 수 없는 자격 증명으로 복원을 진행하지 않는다.

  전체 통과. memory 24705/29536 = 83.64% (하한 83.5%), crewrun 79.56%
  (하한 79.5%). 핵심 3개 파일의 90% 하한도 통과했다.

  HTTP 403과 미저장, 열린 트랜잭션의 다음 문장에서 만료 반영을 확인했다.
  회전 메타데이터·동시 교체 단일 성공·이력 토큰 재사용 거부/롤백·재시도 시
  만료 유지·기존 약한 토큰의 이관/교체도 검증했다.
- Rust 호스트 전체 188개 통과, 기존 ignored 1개. DB 실패와 마지막 설정 저장
  실패의 교체 복구, 회수/다른 principal 상태 응답 거부를 포함한다. Windows
  전용 실행은 이 호스트에서 0개이므로 통과로 계산하지 않았다.
- 실제 Windows에서 `go test -v -count=1 ./cmd/memory-principal` 실행 성공.
  난수 파일 생성·기존 파일 덮어쓰기 거부·보호 DACL의 단일 현재 사용자 ACE를
  검사했다. 테스트 전용 폴더를 확인하고 사용했으며 기존 앱/데이터는 쓰지 않았다.
  실행한 command 소스가 현재 소스와 바이트 단위로 같음을 확인했다.
- Python 도구 90개, Windows Go vet, actionlint와 `git diff --check` 통과.
  Go 복잡도 검사 통과: 5791개 함수 중 기존 부채 381개가 20 초과. 기준값을
  올리지 않았으며 기존 ProvisionPrincipal 분리로 초과 함수 하나가 줄었다.
- 필수 `tools/check_local.py` 전체 통과: Python 90+8+49, Go vet/race,
  복잡도·작업 기록 검사, UI 48개를 포함한다. DB 통합 검사는 위의 별도 결과다.

## 실패를 통해 보강한 부분

처음에는 일부 테스트 호출에 짧은 토큰이 남아 거부됐다. 검증 정책을 우회하지
않고 결정론적인 공개 테스트 전용 토큰으로 호출과 권한 fake를 함께 갱신했다.
이전 버전 스키마를 현재 readiness 규칙으로 만들던 테스트는 실제 과거
마이그레이션만 재구성하는 helper로 바꾸었다. 복구 쓰기 중지 검사의 테이블별
컬럼 목록도 확장했다. 활성 principal만 반환하므로 회수된 HTTP 토큰의 응답은
종전 fixture의 503 대신 403으로 명확해졌다.

최초 도구 검사에서 MINISIGN 환경변수 누락, Rust 의존성 검사에서 sandbox DNS
제한이 있었다. 각각 고정 도구 경로와 허용된 의존성 다운로드로 재검사했다.
직접 RLS 쓰기의 기존 저장소 오류 래핑을 인가 서비스 오류와 혼동한 검사는
거부와 실제 미저장을 확인하도록 수정했다. DB 오류 계약은 바꾸지 않았다.
최초 Windows 실행기는 존재하지 않는 PowerShell 경로를 지정했다. 종료 코드만
확인한 판단을 철회하고, 실제 설치된 Windows PowerShell로 실행해 세 테스트의
PASS 로그와 완료 상태 파일을 확인했다. 실행기 실패를 테스트 통과로 계산하지 않았다.

## 한계와 미실행

현재 Windows 설치 파일은 별도 `2e73b0e` 소스의 서명 빌드이며 이 변경이 없다.
Windows에서 앱 기동→실제 Go CLI→DB 교체·중단 복구·백업 복원으로 이어지는
통합 흐름은 후속 검증이다. 이번 Windows 검사는 토큰 파일 명령의 실제 권한
검사다. 추가 NSIS 패키징·설치·업그레이드, 운영 DB·키·원격 설정 변경과
push·PR·공개 배포는 하지 않았다.

외부 서버의 토큰은 운영자가 회전한다. 데스크톱의 자동 교체는 기동 시 수행한다.
90일 이상 계속 켜진 앱의 무중단 자격 증명 교체까지 검증한 것은 아니다.
토큰 파일과 백업의 보호는 사용자 계정 및 관리자 접근 권한에 의존한다.

커밋 상태: 별도 로컬 변경으로 기록. 외부 push·PR·배포 없음.

후속: 실제 Windows 앱·CLI·DB 교체와 pending 백업 복원 검증 결과는
[후속 작업 기록](2026-10-21-managed-token-runtime-check.md)에 별도로 기록한다.

# run the sys05 condition cells and measure receipt and replay bytes

Task: SYS-05.B (#152)
Research: Engineering measurement with a synthetic in-process plan on an own disposable PostgreSQL; a development run, not a locked comparison, performance claim or tail estimate.
Design: One new test file reuses the pilot harness. Per mode it sends, through the real HTTP handler, a cold search, a burst of six concurrent updates, a worker restart (expired lease, fresh runtime, old claim fenced), a drain and publish, a warm search, a human delete racing a queued update and a search after the delete. The full request denominator is reconciled against the ingress ledger in arrival order. receipt_bytes and replay_bytes are the raw stored JSON slices of native_dynamics.receipt and native_dynamics.input in jobs payloads; a receipt is copied into the capture, event, consumption and state records, so receipt_bytes sums every stored copy and its row count is the number of copies.
Relation: adapted
Deviation: The locked comparison and its cost code were left unchanged; the two new cost slices are filled only in the condition report. The burst check and the burst alterations were split into their own helpers to meet the lint complexity limit.
Why: The pilot and the locked comparison had no restart, burst, delete race or cold/warm cell, and receipt_bytes and replay_bytes were null.
Verified: Against an own disposable PostgreSQL. Async burst: 4 accepted and applied, 2 refused as dynamics_queue_full. Sync burst on one target: 1 accepted, 5 refused as revision_conflict, recorded as observed. Both modes: cold search fell back, warm search selected the published snapshot, the restart fenced the stale claim in async (sync had nothing pending, so no fence was exercised there), the deleted memory stayed deleted, the search after the delete served no source and publication was withheld. receipt_bytes async 5126 over 9 stored copies, sync 3956 over 7 copies; replay_bytes async 2324 over 5, sync 932 over 2. Fourteen altered copies of each real run were refused, and four source mutations of the harness (search that ignores the target, no stale claim, delete skipped, lenient burst check) each failed the test. All TestDynamics tests in internal/memory: 268 passed, 1 pre-existing skip, under plain and -race. golangci-lint v2.14.0 reported 0 issues; the complexity tool added no function above its limit.
Limits: Not accepted. N=1 per cell; the burst reuses one trace, so accepted updates are duplicates, not independent learning. The restart is an in-process runtime swap, not a separate process. In sync the update is applied before the delete, so the race and the restart fence are exercised only in async. The delete race leaves a pending repair, so no repair interval is closed or reported and A-v2 comparison_ready stays false. No sustained overload. The cost slices are logical stored components and overlap ledger_bytes and state_bytes; they are not additive. Full check_local and unrestricted go test ./... were not run. SYS-05 stays in_progress.

## 한국어 작업 기록

제목: sys05 조건 칸을 돌리고 receipt·replay 바이트를 실측
이유: 파일럿과 잠긴 비교에는 재시작·폭주·삭제 경쟁·cold/warm 칸이 없었고, receipt_bytes·replay_bytes가 null이었다.
검증: 자체 임시 PG. 비동기 폭주는 4건 수용·적용, 2건 대기열 가득 거절. 동기 폭주는 같은 대상에서 1건 수용, 5건 revision 충돌 거절(관측대로 기록). 두 방식 모두 cold 검색은 대체 경로, warm 검색은 게시된 스냅숏 사용, 비동기 재시작에서 옛 lease는 막힘(동기는 대기 작업이 없어 막기 검사가 실행되지 않음), 삭제한 기억은 되살아나지 않고 삭제 뒤 검색은 출처 0건, 게시는 보류. receipt_bytes 비동기 5126(저장 사본 9개)·동기 3956(사본 7개), replay_bytes 비동기 2324(5건)·동기 932(2건). 실제 실행을 바꾼 사본 14종은 모두 거절, 시험 코드 변이 4종(대상 무시 검색·옛 claim 없음·삭제 생략·느슨한 폭주 검사)도 모두 실패로 잡힘. receipt는 capture·event·consumption·state에 복사되므로 모든 저장 사본의 합이다. internal/memory의 TestDynamics 전체 일반·race 268건 통과(기존 skip 1건). lint 0건, 복잡도 한도 초과 함수 추가 없음.
한계: 미수용. 칸마다 1회. 폭주는 같은 trace라 독립 학습이 아니다. 재시작은 같은 프로세스 안 runtime 교체다. 동기에서는 update가 삭제 전에 적용되어 경쟁·재시작 막기는 비동기에서만 확인된다. 삭제 경쟁은 repair 대기로 남아 repair 구간을 닫거나 보고하지 않으므로 A-v2 comparison_ready는 false다. 지속 과부하 없음. 비용 조각은 논리 구성요소라 ledger·state와 겹쳐 더할 수 없다. 전체 check_local·무제한 go test 미실행. SYS-05는 진행 중 유지.

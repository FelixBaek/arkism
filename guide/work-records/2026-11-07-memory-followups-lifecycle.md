# Additional memory lifecycle improvements

Task: MEM-FOLLOWUPS-L1-L2-L3-L4-L5-R8
Research: none

## Why / 이유

The lifecycle audit identified six actionable gaps: cumulative extraction budgets reset between chunks, relation names could pick an arbitrary typed entity, interrupted approvals could lose summary scheduling, retired automatic directives consumed active capacity, stale cascades stopped at a fixed listing cap, and conversation adjacency relied on timestamps instead of a producer-supplied order.

파일 전체 예산, 관계 끝점의 모호함, 요약 예약 복구, 자동 규칙의 만료 정리, 대규모 파생 자료의 stale 표시, 대화 조각의 명시 순번을 각각 기존 서비스 흐름에 연결했다. 기존 연구 보류 항목은 변경하지 않았다.

## Contracts / 동작 계약

- L1 uses the existing model-call admission estimate and records reported actual spend, including failed calls. It prevents starting further calls after the aggregate budget is consumed; it cannot retroactively constrain a provider that reports usage above an estimate. Daily ledger limits remain separate. Batch settlement markers are internal job metadata.
- L2 reuses existing approved entity labels as type hints. Exact typed endpoints take precedence; when the existing extractor reused a generic concept node, only one unambiguous generic match is accepted. Multiple generic or typed alternatives remain a conflict. Ambiguous names remain unresolved and the existing bounded recovery job reports conflict; the user must disambiguate the entities or approve a typed correction. No model guesses an endpoint.
- L3 preserves the server-model requirement, scope-level auto_derive opt-in (default off), existing interval/threshold and provider cost limits, service authorization and human summary review. Scheduling alone never calls the model. A running summary pass defers new approval receipts, including the same person already being summarized, without changing its lease or revision. The recovery worker releases its own exact lease for a 30-second delay and refunds only that normal-busy claim; ordinary failures still use bounded attempts. Queue capacity remains 16 people; pending-queue saturation fails recovery visibly rather than silently dropping people. No historical backfill or automatic enabling is introduced. A later settings change does not replay already completed disabled jobs.
- L4 only retires source-linked automatic rules, never independent/manual rules. Retirement increments revision and records retire:directive:source. Retired rules do not automatically reactivate if their source changes later; human review remains available. Future-effective rules retain their active capacity reservation and become applicable when their start time arrives. Context loads active rules directly. Management traverses all stored active, proposed and inactive rules using a scope-bound opaque priority/id keyset cursor, with a bounded page size. Numeric offset cursors are replaced; clients pass next_cursor unchanged. A concurrent priority edit requires restarting a walk; this is not a snapshot of all history. Older repositories without the page capability fail visibly at their fallback cap instead of silently truncating history.
- L5 real database pagination is a new optional repository capability. Older repository implementations without keyset paging fail and roll back at the bounded fallback limit instead of claiming a truncated cascade is complete. The operation remains one atomic transaction; asynchronous multi-transaction cascading is outside this change.
- R8 accepts conversation_order only on conversation sources: epoch matches the existing 1–128 character idempotency label contract, and 1 <= index <= total <= 100000. A slot is immutable and idempotent within scope/origin/source_ref/epoch; a conflicting replacement or retry of a deleted slot is refused. Distinct epochs represent distinct captures and are never joined. Existing records receive no inferred sequence or metadata migration; their bounded legacy timestamp path remains. Repositories lacking the exact-slot neighbor capability do not guess ordered neighbors. The existing conversation source/origin index supports the lookup; no migration is added.

## Verified / 검증

- Review regressions reproduced before correction: scheduling changed a running worker revision; unrelated rule creation permanently retired a future-effective rule. The fixes preserve the running lease and the future rule reservation.
- Genuine pre-fix failures: whole-job chunk/restart budget bypass; arbitrary ambiguous endpoint; lost summary schedule; stale cascade 500/501; expired-rule capacity conflict; explicit conversation neighbors absent despite producer order.
- Final related memory service and temporary database selection passed (5.336s; earlier selection 3.987s), covering all six changes plus existing extraction, provider batches, directives, auto derivation, entity summaries, supersede and conversation behavior.
- Review-focused database and service cases passed (0.842s), including 650 archived rules, future rule activation, same-person running summary deferral beyond five attempts and unchanged running leases.
- Additional database concurrent admission tests passed (0.796s). Host/capture conversation request and existing capture tests passed (0.015s), using local request/model doubles.
- Existing relation-worker regression exposed generic concept reuse by the extractor; exact typed selection now preserves only an unambiguous generic fallback. Existing approval walk tests also exposed missing list-context binding in older repositories; approval now binds the standard transaction listing fallback instead of silently skipping capacity enforcement.
- The summary scheduler's old unit fixture used an invented unsaved approved row. It now references a stored source-backed approved memory, preserving the same person-selection, duplicate scheduling and human-review assertions under the stronger evidence check.
- Go commands used 6 GiB systemd scopes, 900-second timeouts and focused package/test selections. Test database fixtures create and drop isolated disposable databases. No live model invocation or product build occurred. Final targeted checks and commit-format verification are recorded in the commit.

## Limits / 한계

All six assigned items are implemented. API schema/SDK generation and the full-package integration suite are coordinated by the integration owner. The tests establish service/database/producer contracts, not live model answer quality, production throughput, or proof of every possible concurrent interleaving. Pending-queue saturation or permanently failing summary recovery remains visible through the bounded job failure/retry policy. Atomic stale cascade can still be a long transaction for extremely large scopes, although each read page is bounded.

제품 빌드, 실제 모델 호출, 운영 접근, push, PR, 배포는 수행하지 않았다. 기존 데이터의 조각 순번을 추측하지 않았고 보류된 연구를 완료로 표시하지 않았다. 서비스·임시 DB·host 요청 시험의 검증 범위와 운영 성능·실제 모델 품질의 미검증 범위를 구분한다.

요약 작업이 실행 중이면 같은 인물의 새 승인도 후속 예약으로 기다리며, 정상 대기에는 실패 횟수를 쓰지 않는다. 미래 시작 규칙은 미리 폐기하지 않는다. 비활성 규칙도 우선순위·ID 커서로 전체 관리 목록에서 검토할 수 있다. 커서 형식 변경과 동시 우선순위 변경 시 재조회 필요성은 명시적으로 기록한다.

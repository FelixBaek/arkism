# Describe the error bodies that the HTTP service already returns

Task: PR #552 Windows API contract failure
Research: none
Why: The actual-response validator rejected an unknown-field response containing `code: invalid_request` and a string `detail`. The shared HTTP responder already emits detail for validation/revision reasons and database row-policy refusals, but the closed OpenAPI Error object only allowed code. This is a shared transport contract mismatch, not a Windows-specific response.
Changed: Added optional string detail to Error while keeping code required, the error-code enum, and additionalProperties=false. Documented seven missing shared-responder codes: defense_blocked, extraction_disabled, no_extractable_text, model_not_configured, invalid_model_output, handle_taken and model_budget_exceeded. The existing Google sign-in limiter also emits rate_limited, so that code and its 429 response with Retry-After are now documented. Regenerated the TypeScript SDK Error type; Python generation produced no change. Added schema regression cases for optional detail, invalid types, missing code, unknown properties, unknown codes and the additional emitted codes. No handler or validator behavior was changed.
Verified: Under Go 1.27.4, the same Go test selection used by Windows API CI (`^TestMemoryList|^TestHTTPRoutes|^TestOpenAPI`) passed 10 top-level tests and four subtests with no failures or skips, exporting 281 actual handler responses. The original schema rejected that export with the same unexpected-detail error as CI. The amended schema passed `tools/check_openapi.py --cases` for all 437 operations and all 281 responses: 107 success, 70 invalid-request and 104 authentication-required cases, including 65 responses carrying detail. The 102 management operations matched their Go DTOs with update_api_contracts.py --check, SDK generation --check passed, and all 10 check_openapi unit tests passed. An inventory of shared literal mappings, declared flow codes, direct literal error bodies and the model-budget sentinel found no emitted code missing from Error.enum. git diff --check passed.
Limits: Actual response generation used Linux fixture handlers and local httptest providers; this does not claim a completed Windows CI run, live PostgreSQL authorization, external login, model inference or a product build. The 403/409 detail forms and additional error-code cases were schema checks, not newly executed end-to-end service failures. The first local Go attempt was blocked by sandbox loopback-listen permissions; the permitted local test run passed. The first validator invocation also needed the existing configured CI input-root setting to read its temporary evidence file. Neither boundary was removed or weakened.

## 한국어 기록

서버가 이미 반환하던 오류 설명 detail을 OpenAPI가 허용하지 않아 CI가 실패했다. 같은 실제 응답을 로컬에서도 생성해 수정 전 실패와 수정 후 통과를 확인했다. detail은 선택적인 문자열로만 허용하며, 알 수 없는 필드·오류 코드와 잘못된 타입을 거부하는 기준은 유지했다.

누락된 실제 오류 코드와 로그인 횟수 제한 응답을 문서화하고 TypeScript 생성 타입을 갱신했다. 실제 HTTP 응답 281개, Go 계약 검사 10개·하위 4개, 스키마 검사 10개가 통과했다. Windows CI 자체나 운영 서비스 기능 검증을 완료한 것으로 표시하지 않는다.

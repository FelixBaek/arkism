# 메모리 전 영역 추가 개선 후보

작업 ID: MEM-IMPROVE-20261107-AUDIT
연구: 해당 없음

기존 개선 11개를 구현하면서 수집·수명주기, 검색·문맥, 평가·소비자, 저장·운영을 병렬 점검했다. 아래 **22개는 추가 후보이며 구현 완료 목록이 아니다.** 코드에서 확인한 구조와 실제 실행한 검증을 구분했다. 자료 부족으로 보류한 기존 연구는 그대로 보류한다.

## A4. 전체 API 인수 자료의 누락 경로 보완

실행에서 추가 확인한 검사 개선 후보다. `check_openapi.py --cases`는 기존 management 경로 14개의 성공·무인증 응답 자료가 빠져 completeness 검사를 실패한다. 실제 기록된 248건과 새 문맥 2건, 합계 250건의 요청/응답은 개별 schema 검증을 통과했다. 개별 유효성과 전체 경로 커버리지를 구별한다.

기준 커밋과 현재의 management operation 집합이 같고, management manifest·기존 HTTP 사례 생성기·검사기는 이번 변경에서 수정하지 않았음을 확인했다. 누락은 wiki 폴더/페이지/트리/기억 기반 생성 7경로, extension data 3경로, 파일/지식 문서 chunks/history 4경로다. 이 상태를 새 11개 기능의 실패나 전체 API 검증 통과로 바꾸어 표시하지 않는다.

다음 작업은 실제 handler fixture로 이 14개 경로의 성공·401 사례를 보완하고 기존 strict 검사를 다시 통과시키는 것이다. 검사기를 느슨하게 바꾸거나 합성 응답으로 실제 실행 근거를 대신하지 않는다. 이번에는 누락 근거를 기록했으며 추가 경로의 동작 검증까지 완료하지 않았다.

## 점검 범위와 근거 수준

- 수집·중복·승인·규칙·만료·복원·출처·파일/세션 가져오기·엔티티/관계·요약/지식 파생의 대표 구현을 읽었다. 새 4개 수명주기 개선은 서비스와 임시 DB 시험으로 확인하고, 추가 L1–L5는 별도 미구현 후보로 남겼다.
- 검색·순위·시간·그래프·다국어·임베딩·문맥 예산·최종 전달을 읽고 새 옵션의 HTTP/서비스/DB 경계를 실행했다. 실제 모델 답변 품질이나 운영 지연을 입증하지 않았다.
- 평가 수용·신호·동적 상태·관리 UI·호스트·MCP·SDK를 읽었다. API 기능시험과 제품 컴포넌트 브라우저 시험은 서로 다른 경계다. 실제 호스트/모델 세션과 전체 앱의 교정 제출은 실행하지 않았다.
- 저장·이관·백업/복원·삭제·권한·외부 전송·큐·보존 정리·진단은 [저장·운영 점검](2026-11-07-memory-storage-operations-audit.md)에 근거를 기록했다.

기준 패키지의 비시험 Go 파일 421개 목록을 확보했지만 전 파일·전 분기를 상세 검토했다는 뜻은 아니다. 표의 영역별 대표 경로, 기존 시험, 새로 실행한 기능시험을 합친 점검이다. 추가 후보의 실현 가능성·개선량·제품 우선순위는 아직 확정하지 않았다.

기존 11개 구현의 실제 완료 상태와 통합 검사 결과는 [구현 원장](2026-11-07-memory-improvements-progress.md), 개별 변경 이유·시험·한계는 같은 폴더의 lifecycle/context-delivery/feedback-improvements 기록을 따른다.


후속 구현·검증 상태는 [추가 개선 22개 기록](2026-11-07-memory-followups.md)을 따른다.
이 문서의 지적 사항은 구현 전 점검 결과이며, 측정 자료가 필요한 보류와 구현 완료는 후속 기록에서 구분한다.

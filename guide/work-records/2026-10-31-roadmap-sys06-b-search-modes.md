# SYS-06 B explicit off/shadow search mode on the daemon

Task: SYS-06 (#153)
Research: none
Design: A new optional `-dynamics-search-config` file selects the HTTP API search mode. `off` and absent keep the baseline only; `shadow` wires the existing native search shadow, which keeps returning the baseline and records a separate diagnostic. `dynamic` (serving the native ranking) is refused at startup because no serving policy is approved. The file is only valid on the HTTP API next to both dynamics configs; a worker or repair run refuses any search mode file. The shadow registry is read relative to the mode file, pinned by SHA-256, must be a local path and goes through the existing per-component no-symlink reader.
Relation: extends
Why: SYS-06 B needs an explicit, fail-closed mode switch before any dynamic serving can be considered; shadow lets the native ranking be observed on real searches without changing an answer.
Verified: On an own disposable PostgreSQL, `go test ./cmd/memoryd -run '^TestDynamicsIntegration' -count=1` passed 29 in plain and 29 under race with no failure or skip. The config test accepts absent/off/shadow and refuses 19 malformed or out-of-scope files, including a hash-matching registry one level up and at an absolute path (that case failed before the IsLocal fix because filepath.Join cleaned the ".." away), plus off or shadow on a worker or repair run. The PG test runs a worker and two HTTP APIs (off, shadow) on one database and searches off, shadow, off twice: while the worker republishes the shadow fell back as snapshot_unavailable with the same answer, and after the worker stopped and the API cache held one generation the shadow returned selected with the same answer; each search changed only one usage receipt and one search audit event across every table in the schema. `go vet`, gofmt and the repository complexity gate passed. An independent model review first rejected (path escape, side-effect coverage, validation cases, wiring order, goroutine cleanup); after the fixes a second pass accepted with notes. The PostgreSQL cleanup left no databases, roles or backends.
Limits: The lag fallback is observed in every run but not forced deterministically; the row-count check sees inserts and deletes, not in-place updates; the shadow score is bounded only by the clock-drift bracket of the surrounding off searches; JSON keys are matched case-insensitively by the standard decoder. An unreadable snapshot (cache behind the coordinator, withheld or broken publication) first reported the generic reason invalid_source; a follow-up commit reports it as snapshot_unavailable, and the daemon test now asserts that a republishing worker can only cause that fallback (internal/memory native search tests 46 passed plain and race). Dynamic serving, the Story allowlist and the whole-repository check stay open; the full local check and golangci-lint were not run here (lint runs in CI). No product build, deploy or merge was done.

## 한국어 작업 기록

제목: daemon 검색 방식 off/shadow 명시 설정
이유: SYS-06 B는 동적 제공을 검토하기 전에, 실패하면 닫히는 명시적 방식 전환이 필요하다. shadow는 답을 바꾸지 않고 실제 검색에서 native 순위를 관찰하게 한다.
검증: 전용 임시 PostgreSQL에서 `go test ./cmd/memoryd -run '^TestDynamicsIntegration'`을 plain과 race로 돌려 각각 29개 통과, 실패·skip 0이었다. 설정 시험은 absent/off/shadow를 받고 잘못되거나 범위 밖인 파일 19종을 거부했다. 여기에는 해시가 맞는 레지스트리를 상위 폴더와 절대경로에 둔 경우가 포함되며, 이 경우는 IsLocal 수정 전에는 filepath.Join이 ".."를 지워 통과됐다. worker·repair의 off/shadow도 거부했다. PG 시험은 한 DB에 worker 1개와 HTTP API 2개(off, shadow)를 띄우고 off·shadow·off 검색을 두 번 했다. worker가 재게시하는 동안 shadow는 snapshot_unavailable로 fallback했고 답은 같았다. worker를 멈추고 API 캐시 세대가 안정된 뒤에는 selected였고 답은 같았다. 검색마다 스키마 전체 표 중 사용 기록 1행과 검색 감사 1행만 늘었다. go vet, gofmt, 복잡도 검사도 통과했다. 독립 모델 검토는 처음에 반려(경로 탈출, 부작용 범위, 검증 칸, 연결 순서, goroutine 정리)했고 수정 뒤 2차에서 수용했다. PG 정리 뒤 남은 DB·역할·연결은 0이었다.
한계: 지연 fallback은 매번 관찰됐지만 결정적으로 강제하지는 않는다. 행 수 비교는 삽입·삭제만 보고 같은 행 수정은 보지 않는다. shadow 점수는 앞뒤 off 검색의 시계 차 범위로만 묶인다. 표준 디코더라 JSON 키 대소문자를 구분하지 않는다. 읽을 수 없는 스냅숏은 처음에 일반 사유 invalid_source로 보고됐으나, 후속 커밋에서 snapshot_unavailable로 구분했다. daemon 시험은 재게시 중 fallback이 이 사유뿐인지 단언한다(internal/memory native search 시험 46개 plain·race 통과). 동적 제공, Story 허용 목록, 저장소 전체 검사는 남아 있다. 전체 로컬 검사와 golangci-lint는 여기서 돌리지 않았다(lint는 CI). 제품 빌드·배포·병합은 하지 않았다.

# 2026-10-21 공통 HTTP 인가 경계

작업 ID: Task: none (공개 평가 P0-3의 공통 인증·경로별 인가)

## 이유와 변경

서비스 내부 검사만 믿으면 새 HTTP 처리기에서 인가를 누락하기 쉽다. 모든 운영
경로 등록을 `routeRegistrar`로 모으고, `authorizationMux`에서 명시적인
method/path 정책을 요구한다. 설정이 없는 경로는 등록 단계에서 실패한다.
공개 상태·Google 로그인·별도 복구 리스너의 loopback identity 예외도 목록과
회귀 검사에 드러낸다. 무토큰 요청의 기존 403 계약은 유지한다.

실제 소스에는 중복 health/ready 등록을 포함해 273개 패턴, 고유 271개 정책이
있다. 정적 action뿐 아니라 검색 목적, digest 종류, 충돌 대상 두 컬렉션,
privacy 삭제 대상을 실제 요청에서 결정한다. 코드 그래프는 서비스와 같은
프로젝트 범위로 정규화하고, 스킬 제안은 `skill.scope`를 사용한다.

JSON은 각 경로의 기존 상한 안에서 읽고 원문 그대로 되돌린다. 파일 업로드는
첫 metadata 부분과 multipart reader의 작은 선읽기 버퍼만 보관한 뒤 스트림을
복원한다. 본문 경로는 쿼리의 다른 scope를 신뢰하지 않는다. 서비스의 본문·근거·
상태 및 추가 권한 검사는 생략하거나 허용 결과를 캐시하지 않는다.

공통 검사에서 확인한 principal과 role을 요청에 고정한다. 이후 신원이 바뀌면
다음 검사를 모두 거부하고, 서비스가 이를 부분 필터링으로 처리해도 HTTP 응답은
403으로 끝낸다. 응답은 중첩 검사가 끝날 때까지 보류한다. 배치의 이미 완료한
정상 항목은 개별 트랜잭션으로 남지만, 변경된 신원 이후 항목은 저장되지 않는다.

입력 검증 테스트는 새로 추가된 빈 본문의 공통 검사와 실제 본문을 보내는 서비스
검사를 구별한다. 잘못된 입력이 본문 정책·임베딩·작업 저장에 도달하지 않는 기존
검증은 유지했다. 신원 변경 테스트는 전체 응답 거부와 후속 저장 중단까지 강화했다.

공통 검사에서 거절하면 기존 transport 오류 분기가 실행되지 않는다. 이를 숨기려고
하한을 낮추는 대신 직접 서비스 호출 259개를 두 의존성 상태에서 검증하고, 권한
거부·정책 장애 시 운영 저장소 접근을 막는 검사를 추가했다. 모든 JSON 경로는
정상 범위만 허용된 불완전 요청으로 실제 Handler에 진입시켜, 입력 오류나 후속
인가 거절이 성공·외부 호출·운영 데이터 접근으로 바뀌지 않는지 확인한다.

## 실행한 검증

- `go test ./internal/memory -run '^TestHTTP|^TestBatchBoundActor|^TestSearchQuery|^TestSearchRelationInvalid' -count=1`: 통과.
  모든 보호 정책에 대해 검사 없는 처리기를 등록한 뒤 무토큰·잘못된 토큰·권한
  거부·다른 범위·알 수 없는 역할·정상 허용을 검증한다. JSON 원문, multipart
  선읽기/복원, 동적 action과 신원 고정 검사도 포함한다.
- `go run ./tools/complexity`: 통과. 기존 기준값을 올리지 않았다.
- 전체 `tools/check_local.py`: Python 90+8+49, Go vet/race, UI 46개 통과.
- 일회용 PostgreSQL의 `ci_go_test.py --race --integration --coverage --jobs 4`:
  최종 전체 테스트와 커버리지 하한 통과. memory 24632/29451 = 83.64%
  (하한 83.5%), crewrun 1829/2299 = 79.56% (하한 79.5%). 핵심 파일은
  tei 98.61%, candidate_quota 100%, context_budget 97.83%로 하한 90% 통과.
  중간 검사의 82.18%·82.87% 미달은 공통 거부가 앞당겨져 일부 transport 오류
  분기가 실행되지 않은 결과였다. 모든 JSON typed decoder 검사와 위의 직접
  서비스·인가 장애·불완전 요청 검사를 보강했다. 하한은 낮추지 않았다.
- HEAD의 digest 조회와 확정된 twin만 읽는 경우의 최소 권한도 보강했다.
  관련 HTTP·digest·twin 검사는 통과했다.
- Claude의 최신 main `e5f7250`과 Windows 서명 빌드 기록 위로 정리했다. Go 소스·
  설정·fixture와 모듈 파일의 합성 SHA256이 정리 전후 같음을 확인했다. 달라진
  UI 48개와 Python 도구 90개, Go vet·복잡도·작업 기록 검사를 다시 통과했다.

최초 전체 단위 검사는 sandbox의 loopback 소켓 금지로 실패했다. 로컬 테스트
서버를 허용한 실행으로 재검사했다. 중간 회귀 검사에서 발견한 기존 403 계약,
중첩 scope, multipart 요청 상한, 신원 변경의 부분 응답 문제를 수정했다.

## 한계와 미실행

토큰의 강도·발급·만료·회전은 다음 변경이다. 이 변경은 공통의 주 권한 검사이며
각 리소스 상태와 본문 전체에 대한 서비스 검사를 대체하지 않는다. 응답 보류로
현재 비스트리밍 API에 추가 버퍼가 생기며, 향후 스트리밍 API는 별도 설계가 필요하다.
Windows 설치 파일 빌드·push·PR·원격 설정 변경은 하지 않았다. 다른 OS 앱 배포도
추가하지 않았다. 이와 별도로 사용자가 승인한 첫 서명 묶음의 Windows 빌드는
`2e73b0e` 소스로 완료했다. 이 공통 HTTP 인가 변경은 해당 설치 파일에 없다.

커밋 상태: 로컬 작업 브랜치의 별도 변경으로 기록. 외부 push·PR·배포 없음.

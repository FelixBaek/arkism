# 2026-10-21 Windows 자동 시작 등록과 제거

작업 ID: Task: none (공개 평가 P1-7, 제거 후 자동 시작 등록 잔여)

## 이유와 변경

기존 자동 시작 라이브러리는 관리자 실행 때 HKLM을 먼저 시도하고 Windows
실행 경로를 따옴표 없이 기록한다. 설정에서 해제하는 경로와 NSIS 제거 경로도
이어지지 않았다. Windows에만 현재 사용자 레지스트리 정책을 적용했다.
다른 OS의 기존 구현은 바꾸지 않았다.

- 공백이 있는 실행 경로도 따옴표로 감싼다. 앱 설정과 headless
  `--remove-autostart`가 같은 코드를 사용한다. helper는 GUI, DB, 에이전트,
  단일 인스턴스 초기화 전에 종료하며 추가 인자는 거부한다.
- 해제는 현재 실행 파일을 정확히 가리키는 Run 명령에만 적용한다. 해당
  StartupApproved 값도 같은 Windows 레지스트리 트랜잭션에서 지운다.
  다른 설치 경로의 등록과 이웃 값은 남긴다. 실패하면 두 값 모두 원복된다.
- 기존에 이 앱이 만든 명령의 따옴표만 보강한다. 작업 관리자의 비활성 상태는
  유지한다. 새로운 활성화는 HKCU만 사용한다. 잠금 파일에 이미 있던
  windows-registry 0.6.1을 직접 의존성으로 고정했고 버전 갱신은 없다.
- NSIS는 helper 성공을 확인한 다음 파일을 지운다. 실패·파일 누락·15초
  응답 지연이면 payload 삭제를 중단해 복구할 프로그램을 남긴다.
  Windows Checks와 Release preflight에 공유 NSIS 매크로의 무해한 대조 검사를
  추가했다.

## 실행한 검증

- Windows Rust 전체 286개 통과, 기존 opt-in 4개 ignored. 이 중 새 정책
  10개는 현재 사용자 등록, 공백 경로, 이웃·다른 경로 보존, 작업 관리자 비활성,
  기존 형식 보강, 누락 키 비생성, 활성화·해제 트랜잭션 원복을 확인한다.
  실제 테스트 키 8개가 모두 사라졌고 검증 경로의 남은 프로세스는 0개였다.
- 호스트 Rust 회귀 193개 통과, 기존 ignored 1개. 다른 OS 설치 파일은
  만들지 않았다. Go/UI 소스를 바꾸지 않아 해당 전체 검사는 반복하지 않았다.
- 실제 Windows의 공유 NSIS 매크로 대조 4개 통과: 정상, 종료 코드 7 오류,
  실행 파일 누락, 실제 15초 시간 초과. 오류 세 사례는 sentinel 파일이 남는다.
  정상 사례만 지운다. helper 인자와 남은 프로세스 0개도 확인한다.
- 제품 NSIS 소스도 가짜 payload로 컴파일했다. 생성한 설치/제거 프로그램은
  실행하지 않았다. Windows 검증 앱을 별도로 빌드했고 정리 flag의 추가 인자를
  실제 바이너리가 종료 코드 2로 거부함을 확인했다. 기존 배포용 설치 파일은
  바꾸지 않았다.
- Windows 설치 smoke 오프라인 76개와 제품 제거 정책 오프라인 139개 통과.
  실제 제품 효과는 실행하지 않는 검사다. actionlint와 diff 공백 검사도 통과.

네이티브 검증 스냅샷 SHA256은
`18693a4941082a7500008167debc24e1dc3cd10e191d330a70b067b41ce90f39`다.
현재 Rust·잠금 파일·제품 NSIS·공유 매크로를 해당 스냅샷과 바이트 단위로
대조했다. 검증 실행 파일 SHA256은
`f576b9f0cd4bc48ca7529e3cc87906aa6f09b67102cbaf3eb5f5dc7f863ada79`다.
비밀이 없는 상태·로그·JSON은 별도 로컬 근거 폴더에 보관한다.

## 실패와 보강

처음 SSH 세션에서 분리해 띄운 검사에 상태 파일이 없었다. launcher의 성공을
검사 성공으로 인정하지 않고 연결을 유지하는 실행으로 바꾼 뒤 실제 종료 코드와
상태·로그·증거 파일을 확인했다. 콘솔 peer 컴파일에는 Windows PowerShell이
필요하므로 그 전제와 CI 셸을 명시했다. 제품의 기존 수동 FFI 선언 경고는
이번 자동 시작 정책으로 해결되었다고 주장하지 않는다.

## 한계와 미실행

실제 사용자 시작 키·설치된 프로그램·사용자 데이터는 바꾸지 않았다. 네이티브
레지스트리 검사는 새 소유 namespace만 사용하고, 삭제 전 정확한 키와 소유
마커를 확인한다. NSIS 대조 프로그램은 자체 임시 파일만 다룬다.

실제 제품 설치/제거와 활성 Run 키를 결합한 검증, HKLM의 과거 등록 정리,
소유권을 증명할 Run 값이 없는 고아 StartupApproved 정리는 미실행이다.
기존 제품 제거 smoke의 Run 키 부재 검사는 활성 등록 제거의 증거로 주장하지
않는다. 설치 중 파일 단위 덮어쓰기와 고정 Sleep, SSH 최초 지문 확인,
UI 구조 개선, OpenAPI 계약 강화 등 전체 평가의 나머지 항목은 남아 있다.

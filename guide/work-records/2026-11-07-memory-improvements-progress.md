연구: 해당 없음

## 검증 기준

- 코드가 존재하는 것과 실제 기능이 동작하는 것을 구분한다. 실제 Capture/승인/Search/BuildContext/worker/API/UI 경계를 통과하는 시험을 각 항목에 연결한다.
- 버그 후보는 수정 전 실패와 수정 후 성공을 기록한다. 정책 변경은 기존 정책을 보존한 명시적 옵션과 비교 검증을 포함한다.
- 범위·권한·삭제·격리·원본 revision 검증, frozen context 및 외부 전송 경계를 유지한다.
- Go 검사는 메모리 패키지로 제한하고 `systemd-run --user --scope -q -p MemoryMax=6G timeout 900 go test ./internal/memory`로 실행한다. 관련 기능시험 후 통합 패키지를 확인한다.
- UI는 관련 로컬 시험, 로컬 코드 검사, 실제 화면·키보드 확인을 별도로 기록한다.
- 고정 오프라인 검색 평가는 기존 하네스·잠금·입력·예산을 유지한다. 모델 호출 감지 결과와 모든 분류의 행별 차이를 확인한다.
- 제품 빌드·운영 배포·원격 push는 이번 작업에 포함하지 않는다. 필요한 테스트 실행 파일과 승인된 오프라인 하네스만 사용한다.

2. 엔티티·관계·관찰·반영·요약·지식 파생과 작업 복구
3. 검색·순위·시간·그래프·임베딩·다국어·문맥 예산과 실제 전달
4. 피드백·평가·신호·동적 상태·UI·호스트/도구/SDK 연결
5. 저장소·이관·백업/복원·개인정보 삭제·권한/범위·외부 전송
6. 작업 큐·임대/재시도·보존 정리·관측/진단·확장 연결과 운영 경계

각 점검 기록은 본 파일과 별도의 근거 보고서에 조사 파일·기존 시험·확인된 동작·개선 가설·미실행 검증을 구분한다. 파일 목록만 확인한 것을 상세 검토 완료로 표시하지 않는다.

## 현재 검증

세 구현 작업의 로컬 커밋을 전용 통합 트리에 합쳤다. 교차 검토에서 발견한 재색인 충돌, dry-run의 fence 쓰기, 시간만료/미래 기억의 일괄 추출 중단을 실제 DB에서 재현하고 수정했다. 엔티티 잠금 순서도 통일했다. 최종 메모리 전체 시험과 고정 오프라인 검색 평가를 완료했다. 아래 통합 결과와 API 커버리지의 남은 한계를 구분한다.

API의 세 옵션과 규칙 원본 상태, ContextPack 실제 필드를 반영하고 DTO/SDK 계약을 갱신했다. OpenAPI 구조 검사(433 operations), DTO 일치(101 management operations), 관련 검사기 8개 및 SDK 생성기/로컬 HTTP 왕복 6개가 통과했다. SDK 시험의 초기 sandbox loopback 제한은 격리 loopback 허용 실행으로 해결했다.

전 영역 추가 후보 22개는 [추가 감사 기록](2026-11-07-memory-full-audit.md)에 별도로 정리했다. 이 후보들은 이번 11개 구현 완료 수에 포함하지 않는다.

추가 실제 HTTP 계약 검사: 기록된 기존 248건과 새 문맥 2건은 개별 schema 검증을 통과했다. 단, strict 전체 커버리지 검사는 기존 management 14경로의 성공·401 자료 누락으로 실패한다. 기준 operation 집합과 기존 생성기/검사기가 변하지 않았음을 확인했으며, 검사기를 완화하지 않고 추가 후보 A4에 기록했다. 전체 API 인수 통과를 주장하지 않는다.

## 고정 오프라인 검색 평가

잠금 아래 기존 하네스·입력·검색 예산을 그대로 사용했다. 453개 질문을 limit 10과 50으로 각각 실제 격리 서버에 조회했다(906개 검색 요청). 정답 근거가 있는 451개 질문을 채점했고 누락·중복 질문은 없었다. 기본 정책 평가이며 새 opt-in 정책의 일반적인 답변 품질 향상을 입증하는 시험은 아니다.

| --- | ---: | ---: | ---: | ---: |
| 여러 사실 조합 | 93 | 0.5955 | 0.5955 | 0 / 0 |
| 시간 | 87 | 0.9109 | 0.9109 | 0 / 0 |
| 개방형 | 32 | 0.6146 | 0.6146 | 0 / 0 |
| 단일 사실 | 239 | 0.9707 | 0.9707 | 0 / 0 |
| 전체 | 451 | 0.8565 | 0.8565 | 0 / 0 |

이번 작업의 직접 기준인 이전 검산본과 비교하면 R@10의 실제 근거 집합도 모든 행에서 같았다. 기억 단독 R@10=0.747265, 기억+대화 R@50=0.936947도 행별 개선/악화가 모두 0이었다. 더 오래된 기준본과의 기억 단독 차이는 선행 작업의 1개 개선·1개 악화를 그대로 상속했으며, 이번 변경의 새 개선으로 세지 않았다.

모델 호출 trap 0건, 비임베딩 provider usage 0→0, degraded 응답 0건이었다. 기존 로컬 임베딩과 고정 자료만 사용했으며 모델 답변을 생성하지 않았다. 검색 근거 매핑은 하네스의 개발용 근사 기준이고 실제 답변 정확도가 아니다.

검산 바이너리는 dcab7f64의 생산 코드로 만들었다. 빌드 시 dirty 표시는 API/SDK 문서와 시험용 응답 기록 변경에서 왔다. 이후 생산 코드 수정은 ExtractEntities의 출처 없는 입력 선별 한 곳이며, 검색 경로·저장 자료·하네스는 바뀌지 않았음을 diff로 확인했다. 이후 시험 수정은 목록 조회 전 snapshot 및 deadline 동기화이며 검색 품질 비교에는 영향을 주지 않는다. 검산 컨테이너와 API/임베딩 캐시/trap 서버의 종료를 확인하고 이번 임시 바이너리·서버 파일을 정리했다. 평가 결과는 별도로 보존했다.

## 최종 통합 결과

- `systemd-run --user --scope -q -p MemoryMax=6G timeout 900 go test ./internal/memory -count=1 -json`: **PASS, 276.125초**. 실제 임시 PostgreSQL 및 로컬 백업 도구를 지정했다. 최상위 시험 1,967개 통과, 세부 subtest 포함 6,869개 통과, 실패 0개다.
- 별도 설정/자료가 필요한 시험은 최상위 16개, subtest 포함 **23개 skip**이다. 호스트 invocation fixture, MCP subprocess 바이너리, 고정 연구 입력·측정 lock, 실제 모델 handoff, export/copy DB 설정 등이 대상이다. 미실행을 통과로 세지 않았으며 운영·실모델 인수로 일반화하지 않는다.
- 통합 전후 발견한 재색인 충돌, dry-run fence 쓰기, 시간만료/미래/출처 없는 기억의 일괄 추출 중단을 수정했다. 목록 조회 시험은 승인 응답의 옛 내부 fence 대신 조회 직전 DB 전체 레코드와 비교하도록 강화했다.
- 마지막으로 기존 30ms timeout 시험의 호출 전 만료를 지연 주입으로 재현했다. 시험에서 실제 HTTP 도착 뒤 DeadlineExceeded를 발생시키도록 동기화했다. 제품 시간 제한과 단일 호출·실패원장 검사는 그대로다. 실패 유형 전체 30회 및 timeout race 30회 통과 후 위 최종 전체 검사가 통과했다.
- UI 관련 3개 시험 파일 통과. 실제 제품 컴포넌트와 CSS를 띄운 브라우저에서 평가 이력·재시도·페이지 추가·작업 근거·교정 callback·규칙 상태/수동 재승인·키보드·좁은 화면을 확인했다. 합성 HTTP 응답을 사용했으며 전체 앱/실제 서버의 교정 제출 E2E는 아니다. 로컬 디자인 검사기는 JS/MJS를 지원하지 않아 코드 검사 통과로 표시하지 않았다.
- OpenAPI 구조·참조 433 operations, 관리 DTO 일치 101 operations, SDK 생성물 일치, 검사기 8개와 SDK 생성기/로컬 HTTP 왕복 6개 통과. 실제 기록된 요청/응답 250건의 개별 schema가 유효하다. **전체 API 인수 커버리지는 기존 14경로 자료 누락으로 미통과**이며 추가 과제 A4로 남긴다.
- 변경 Go 파일의 gofmt, 공백 검사, 금지 파일명 검사를 통과했다. 공개 금지 ignore/example 파일은 변경에 포함하지 않았다.

## 적용할 때 알아둘 점

새 문맥 선택지와 평가 회복 정책은 명시적으로 켜야 한다. 기본 검색 결과의 근거 회수는 기존과 같았다. 긴 항목을 통째로 제외하는 정책은 유일한 정답도 놓칠 수 있어 기본값을 바꾸지 않았다.

원본 scope/rule 연결이 없는 오래된 자동 규칙은 적용을 멈추고 `needs_review`로 남는다. 삭제하지 않으며 화면에서 사람이 다시 승인할 수 있다. 사람이 수정하거나 끄는 경우에도 독립 수동 규칙으로 바뀌므로, 이후 원본 변경·만료와 별도로 유지된다는 안내를 표시한다. 신규 관계 복구 worker는 문서화한 기존 작업 권한과 기억 읽기·엔티티 쓰기 권한이 필요하다.

## 보관 및 정리

구현·검증·추가 후보 문서는 전용 통합 작업본에 보관한다. 이번 임시 DB, 검산 컨테이너/서버/바이너리를 종료·정리했고, 통합된 깨끗한 작업용 워크트리 3개를 제거했다. 로컬 커밋과 검증 결과는 보존했다. 기존 작업본과 다른 작업의 변경은 수정하지 않았다. 원격 push·PR·배포는 이 작업에 포함하지 않았다.

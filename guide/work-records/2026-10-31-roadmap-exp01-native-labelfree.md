# EXP-01 label-free native run through the product's own memory paths

Task: EXP-01 (#153)
Research: none
Design: An opt-in PG test reads only `events.jsonl` and `queries.jsonl` from a directory that must hold exactly those two regular files; every label-free field is declared and the decoder refuses unknown keys, so a gold or label field cannot reach the run, and the input sha256 values go into the run manifest. Each stream gets its own fixture and scope on a disposable PostgreSQL. Material events become an agent-proposed source and candidate that a human approves; a revision named by a later `correction_proposed` in the same stream waits as a candidate (lookahead, stated in the manifest), the proposal marks a conflict holding the candidate, the commit approves it with `replace_old`, and a delete deletes the current memory. Task, exposure and outcome events are assumed to have no baseline search input. Each query runs the product search (exact+fts; historical requests add inactive rows because there is no as-of search). A hit counts as a plan ref only when its product `collection:id` is bound and its text hashes to the plan text; a product id is never re-pointed. Every step records the plan fields the product call dropped, and a step the harness could not run because an earlier one failed is `harness_cascade`, not a product refusal. Scoring stays outside the repository in the evidence folder, after the run.
Relation: extends
Why: The EXP-01 card needs a contract under which the product runs on execution input with the answers removed; the owner approved a test-only native run.
Verified: `TestEXP01NativeLabelFreePG` ran three times on a fresh disposable PostgreSQL each time (plain, race, race); materialization and manifest were byte-identical and answers were identical after removing the random product ids. 14 events: 7 applied, 7 no product input, none refused or cascaded; 11 queries answered with no unmapped, mismatched or degraded hits. `TestEXP01InputsRefuseLabels` covers a gold file, a label key inside queries, a malformed delete and a symlinked input. go vet and gofmt on the new file passed. Development scoring (11 queries, descriptive only): primary 6/6, 5/6 without a post-as-of revision; one clear negative returned the forbidden revision. An independent model review first rejected (name-only label guard, revision mapping by id alone, refused search scored as abstention, lenient historical scoring, cascade misattribution); after the fixes the second pass accepted, and its follow-ups (step-status gate, degraded exclusion, lookahead note) were applied.
Limits: Plan times, scope user/agent, summary and outcome are dropped; the product clock is wall time, so as-of state is not reproduced. Search goes through the admin connection, so row-level security is not exercised. No vector lane. The agent candidate carries a fixed placeholder generator. 11 synthetic queries from one plan; no effect or policy claim. EXP-01 final lock still needs the EXP-02 pilot. No product build, deploy or merge was done.

## 한국어 작업 기록

제목: EXP-01 정답 없는 입력으로 제품 기억 경로를 그대로 실행
이유: EXP-01 카드는 정답을 뺀 실행 입력만으로 제품이 동작하는 계약이 필요하다. 소유자가 시험 코드만 쓰는 실행을 승인했다.
검증: 임시 PostgreSQL을 매번 새로 띄워 세 번(plain·race·race) 돌렸고, 실행 기록과 manifest는 바이트가 같았으며 답은 무작위 제품 ID를 빼면 같았다. 사건 14개 중 적용 7개, 제품 입력 없음 7개, 거절·연쇄 실패 0개였다. 질문 11개 모두 답했고 대응 실패·내용 불일치·degraded는 0이었다. 정답 파일, 질문 안 라벨 필드, 대상 없는 삭제, symlink 입력을 거부하는 시험이 통과했다. go vet과 새 파일 gofmt가 통과했다. 개발용 채점(11문항, 기술 통계만): 주 문항 6/6, as-of 이후 판을 빼면 5/6, 명확한 음성 문항 1개는 금지된 판을 돌려줬다. 독립 모델 검토는 처음에 반려했고 수정 뒤 2차에서 수용했다. 후속 요청(단계 상태 검사, degraded 제외, 미리보기 명시)도 반영했다.
한계: 계획의 시각·사용자/에이전트 범위·요약·결과는 버려지고 제품 시계는 실제 시각이라 as-of 상태를 재현하지 않는다. 검색은 관리자 연결이라 행 단위 보안을 거치지 않는다. 벡터 검색은 없다. 에이전트 후보의 생성기 정보는 고정 자리표시값이다. 한 계획의 합성 질문 11개라 효과·정책 주장은 없다. EXP-01 최종 잠금은 EXP-02 파일럿이 더 필요하다. 제품 빌드·배포·병합은 하지 않았다.

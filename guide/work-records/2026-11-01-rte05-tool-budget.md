# RTE-05 CLI tool accounting and workflow stop propagation

Task: RTE-05 (#155)
Research: none
Design: Count CLI-reported tool invocations separately from model turns. Claude-family runs request verbose stream-json; Codex exec requests JSONL. Deduplicate reported invocation IDs, preserve final answer text, and expose only a versioned count summary. Routing fallbacks and workflow retries/model fallback share the logical AI call's 50-call accounting limit and wall-time deadline. A failed attempt that has already used 50 calls cannot dispatch another attempt. Failed attempts with an exceeded/unknown count or a started answer stop; workflow retries and model fallback respect both direct and routed terminal results.
Relation: adapted
Deviation: Enforcement is post-run, as allowed by the owner's existing decision. The CLI may already have crossed the limit. Counts cover observable CLI invocations, not hidden provider work or recursively hidden tool calls. This extends the invocation/result adapters and their workflow consumers because the routing loop alone cannot observe individual tools.
Why: A turn can contain multiple tools. The previous turn cap therefore did not implement the requested tool-call bound. A local runner subprocess also reproduced eight dispatches after a terminal result: four retries on the original model and four on the replacement. The consumer now preserves that terminal boundary.

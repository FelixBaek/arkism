# 2026-10-21 Windows 설치 프로그램과 복구 코어 연결

작업 ID: Task: none (공개 평가 P1-7, 설치/업데이트 교체와 제거)

## 이유와 변경

앞선 Windows 교체·등록 복구 코어를 제품 NSIS와 두 Windows 빌드 경로에
연결했다. `arkism-installer.exe`는 설치 폴더 밖에 추출해 실행한다. 공개 명령은
현재 사용자와 고정 Arkism 등록만 사용하며, 임의 registry hive나 장애 주입
옵션을 제공하지 않는다. 네이티브 연결 검사는 private 함수의 metadata factory와
확인 함수를 통해 전용 registry·바로가기 공간에 같은 구현을 연결한다.

패키징은 같은 NSIS 소스를 두 번 컴파일한다. 첫 빌드 전용 프로그램은 자기
소유의 새 임시 폴더에 제거 프로그램만 생성한다. 이를 선택적으로 Authenticode
서명한 뒤 전체 payload의 목록·크기·해시를 고정하고 최종 설치 파일에 포함한다.
설치 중 다른 제거 파일을 다시 만들지 않는다. 기존 minisign 서명이 인증한
설치 파일 안에서 얻은 목록이라는 신뢰 경계를 명시했다. JSON 자체를 독립적인
게시자 인증으로 취급하지 않는다. 보조 프로그램도 runtime과 SBOM 검사에 포함된다.

설치 전 전체 추출물을 검사하고, 기존 프로세스의 실제 이미지와 종료를 확인한
뒤 payload·바로가기·등록을 교체한다. 실패·시간 초과는 복구 명령을 실행하며,
미완료 payload를 자동 실행하지 않는다. 완료 기록 뒤 정리 경고는 완료한 설치를
원복하는 실패로 반환하지 않는다. 이전 설치 위치와 `/NoAutoRun` 동작을 유지한다.

제거는 등록 위치와 정확한 버전을 확인하고 프로세스를 종료한 뒤 연결 해제와
공유 자동 시작 정리를 실행한다. 각 종료 코드를 확인한다. 프로그램 파일은
완료한 설치 기록의 목록·해시와 일치하는 것만 핸들로 확인해 제거한다. 전체
파일 검사를 마치기 전에 삭제하지 않는다. 알 수 없는 파일, 수정된 파일,
외부 바로가기와 registry 값은 보존한다. 비어 있지 않은 폴더를 재귀 삭제하지
않으며, 실패 시 남은 파일과 설정을 보존했다는 메시지를 표시한다.

## Windows 경로 보호

환경 변수만 바꾼 자식 프로필에서 Windows Programs는 테스트 폴더를 사용했지만
Desktop은 실제 OneDrive 경로를 반환하는 것을 읽기 전용 검사로 발견했다.
환경 변수 격리만을 설치 검사 안전 조건으로 취급하지 않는다.

`check-folders`는 실제 설치 adapter와 같은 Windows known-folder 조회 및 물리
경로 확인을 사용한다. 지정한 예상 경로와 비교만 하며 등록·바로가기를 쓰거나
Windows 폴더 설정을 변경하지 않는다. 설치·제품 제거·무동작 자동 실행 검사에
공통 사전 확인을 연결했다. 테스트 소유 폴더를 먼저 만들고 이 확인을 통과하기
전에는 설치 파일을 실행하지 않는다. 절대 Desktop 설정을 사용하는 호스트는
안전하게 실패하며, 실제 사용자 폴더를 우회 경로로 채택하지 않는다.

- 실제 Windows Go 전체 검사: 하위 사례 159개 통과. installtxn 문장 커버리지
  79.3%, 보조 CLI 90.1%. 기존 실제 프로세스 종료 후 복구 26개를 포함한다.
  전용 registry와 COM 바로가기로 패키지 확인→설치→등록 확인→설치 기록에
  따른 제거를 연결했고, 완료 후 보관 실패의 복구 명령도 검증했다.

  무동작 payload를 사용했고 제거 파일 생성 프로그램만 실행했다. 제품 설치·제거
  실행이나 완성된 실제 앱 전체 빌드로 계산하지 않는다.
- 실제 shipping 보조 프로그램의 읽기 전용 `check-folders`가 환경 변수만으로
  격리되지 않은 Desktop을 종료 코드 1로 거부했다. 실제 사용자 폴더 설정은

  남아 있지 않음을 별도로 확인했다.
- 실제 Windows에서 오프라인 설치 wrapper 77개와 제품 제거 정책 139개 통과.
  설치·런타임 효과는 가짜 구현이며 이를 제품 설치·제거 성공으로 계산하지 않는다.
  경로 확인 실패가 설치 실행보다 먼저 발생하는 사례도 포함한다.

## 실패와 남은 한계

초기 Windows PowerShell 검사의 출력을 SSH로 직접 전송하다 진행이 멈췄다.
이번 작업의 명령줄로 소유권을 확인한 검사 프로세스만 중단했다. 이미 완료한
Go 검사와 패키징 결과를 전체 스크립트 통과로 계산하지 않았다. 최종 연결
검사와 오프라인 검사는 Windows 파일에 모든 스트림을 기록해 다시 통과했다.
무동작 fixture와 빌드용 제거 프로그램은 소유 빌드 공간에 근거로 남겨 두었다.

실제 제품의 새 설치·업그레이드·제거와 활성 Run 등록 제거를 실행한 것은 아니다.
격리 검사는 disposable hosted Windows의 실제 알려진 폴더 경로가 예상 테스트
폴더와 일치할 때만 진행할 수 있다. 원격 CI/Codecov patch 80% 판정은 미실행이며,
로컬 문장 커버리지와 동일한 지표로 표시하지 않는다. 보관 버전의 개수·용량
제한도 아직 없다. 제거의 여러 명령 전체를 하나의 잠금으로 묶는 작업은 남아
있으며, 단계별 소유권 확인을 전체 제거의 원자성으로 해석하지 않는다.

실제 앱 전체가 포함된 앞선 서명 빌드는 `2e73b0e` 소스이고 이번 후속 변경을
포함하지 않는다. 이번 작업은 소스·Windows 연결 검증이며 push·PR·공개 릴리스,
운영 서명 키 등록이나 실제 사용자 데이터 변경을 수행하지 않는다.

## 변경 이유와 구현

기억은 이미 서버 페이지를 요청했지만, 화면의 행은 ‘더 보기’ 횟수만큼 계속
늘어났다. 후보·충돌·스킬·휴지통은 시작과 갱신 때 여러 서버 페이지를 연속으로
읽었으며, 개요 창에는 기억 10만 개를 연속으로 다시 읽는 별도 루프도 있었다.

공통 커서 전송기를 사용해 각 목록은 첫 50개만 읽는다. 다음 페이지는 사용자의
‘더 보기’에서만 요청한다. 화면의 로컬 필터 결과가 없어도 다음 페이지 버튼을
유지한다. 후보·스킬 검색·분류·묶음과 개수·정렬이 불러온 항목 기준임을 명시한다.
홈 요약도 부분 목록임을 설명하고 스킬 개수에 다음 페이지가 있으면 +를 붙인다.

전송기는 실제로 읽은 페이지 수를 저장한다. 빈 페이지·중복 ID·보류된 스킬로
항목 수가 작아져도 갱신 범위가 사라지지 않는다. 여러 클릭에 걸친 커서 순환을
거부한다. 오류 시 이전 페이지 창을 유지하고, 실패한 갱신은 같은 범위로 재시도한다.
충돌·휴지통의 선택적 갱신 실패도 이미 읽은 항목을 빈 배열로 대체하지 않는다.

150행을 넘긴 목록은 측정한 행 높이와 Fenwick tree로 화면 주변 행만 표시한다.
초점이 있는 행은 스크롤로 사라지지 않도록 한 행만 추가 유지한다. Tab/Shift+Tab,
위/아래, Home/End를 지원한다. 너비·본문 길이에 따라 실제 높이를 갱신하고 화면을
떠나면 관찰자·리스너를 해제한다. 입력·행 초점을 복원하고 검색창 커서도 보존한다.
가상화 래퍼 때문에 행 구분선이 없어지는 CSS 문제는 실제 화면에서 찾아 수정했다.

닫힌 후보 묶음은 내부 행을 만들지 않는다. 펼친 묶음은 50개씩 이전/다음으로
이동한다. 원문 근거 확인은 기존처럼 최대 32개·동시 두 요청이며, 일부만 확인한
결과를 전체 근거로 표시하지 않는다. 오래된 후보 만료 확인문은 불러온 수와 서버가
최대 100개 처리하는 범위를 구분한다. 실제 후보 처리·삭제는 실행하지 않았다.

후보 묶기는 조건·부정·수치·scope 경계를 보존한 Map 인덱스로 바꾸었다.
스킬 묶기의 반복 배열 복사와 휴지통 ID의 반복 선형 검색도 제거했다.
화면 갱신의 읽기 계획·결과 게시·스케줄, 후보 묶음 표시, 행 초점, 스킬 유사도를
각 모듈로 나눴다. 기존 스킬 유사도 기준과 상위 20개 동률 순서를 유지하며 큰
목록은 작업을 나눠 입력을 막지 않는다. 결과는 20개만 보관하고 잠금·새 목록은
이전 계산을 취소한다. 새 스킬 페이지의 버전 검사 누락도 수정했다.

`app.js`는 2,215→2,130줄, `memoryList.mjs`는 401→356줄이다.
코드 줄 수만으로 복잡도 전체가 해소됐다고 주장하지 않는다. Go/Rust 대형 함수의
기존 복잡도 부채는 이 UI 변경에서 정리했다고 주장하지 않는다.

## 문서·CI와 남은 한계

새 [목록 문서](../list-performance.md), UI 구조·개발·품질 가이드, 변경 기록을
현재 동작에 맞췄다. Windows 브라우저 CI는 소스와 번들을 각각 검사하고 7개
화면을 비교하며 증거를 보관하도록 추가했다. ruleset 파일에는 새 검사도 제안한다.
워크플로 구문 검사와 실제 원격 실행·서버 규칙 적용은 별개다.

Windows Actions·실제 Windows WebView·설치/업데이트는 미실행이다. 새 Windows
설치파일은 만들지 않았으며 이전 전달 파일에는 이번 변경이 없다. push·PR·공개
게시·GitHub 규칙 변경도 실행하지 않았다. 로컬 브라우저의 합성 API 검사는
실제 DB·외부 provider 통합 검증을 대신하지 않는다.

전체 서버 집계·정렬·저장소 목록, 후보·스킬의 서버 전체 본문 검색, 커서 없는
지식·자동화 등 API에 새 분할 계약을 추가하는 일은 남는다. 읽은 데이터 배열은
유지되므로 DOM 가상화가 클라이언트 메모리 상한을 뜻하지 않는다. 유사도 비교는
입력에 제어를 돌려주지만 최악의 작업량은 여전히 이차식이다.

커밋 상태: 코드·검증·문서를 로컬 커밋으로 기록한다. 공개 저장소에는 게시하지 않는다.

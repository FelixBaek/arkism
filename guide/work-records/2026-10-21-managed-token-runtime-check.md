# 2026-10-21 Windows 실제 토큰 교체·복원 검증

작업 ID: Task: none (공개 평가 P0-3, 토큰 수명 관리의 Windows 통합 검증)

## 이유와 변경

토큰 API와 복구 상태 단위 검사만으로 실제 데스크톱·Go CLI·PostgreSQL 연결이
동작한다고 주장할 수 없다. 기존 `--runtime-check DIR`에 관리 토큰의 수명·교체·
복원 검사를 추가하고 실제 Windows 검증 앱으로 실행했다. 진단 구현은 별도
`runtime_token_check.rs`로 분리했다. 앱의 IPC에는 이 작업을 노출하지 않는다.

진단은 절대 경로의 새 폴더만 받는다. 기존 데이터, 링크/junction이 있는 상위
경로, 잘못된 경로는 런타임 기동 전에 거부한다. 소유 마커와 isolated runtime을
함께 확인한 뒤 테스트 DB만 변경한다. 고정 모델 설정도 진단이 직접 준비해
외부 모델 선택을 막는다. 설치 smoke 래퍼는 폴더를 미리 채우지 않는다.

실제 경로에서 확인하는 사례는 다음과 같다.

1. 교체 시각에 가까운 owner/worker를 정상 앱 기동으로 교체한다.
2. DB 교체 전 저장된 pending 키를 다음 기동에서 완료한다.
3. DB 교체 후 파일 기록이 끝나지 않은 상태를 같은 키 쌍으로 재시도한다.
4. pending 상태가 들어 있는 형식 2 백업을 지우기/복원 경로로 복구한다.
5. 각 단계에서 이전 토큰은 HTTP 403, 새 토큰은 HTTP 200인지 확인한다.

중단 양쪽의 디스크/DB 상태를 재구성하는 검사다. 실제 PC 강제 종료나 전원
장애를 실행했다고 표현하지 않는다. 별도의 단위 검사는 저장 실패도 주입한다.

staged/installed 게이트에서 같은 검증 함수를 사용해 다섯 항목의 실제 Boolean
성공을 요구한다. 항목 누락, false, 문자열 `true`, 완료 전 단계, 과거 바이너리의
오래된 보고서는 거부한다. 검사 폴더 이름은 실행마다 새 GUID로 만든다.

## 실행한 검증

- 최종 Windows 소스 기준은 `ea7ef9e`와 진단 변경의 고정 스냅샷이다.
  스냅샷 SHA256:
  `02d1eaedaa9713263371956de51d200cd66c60fd0ece0c651a304aaf72ebabd8`.
  현재 진단·게이트 소스와 스냅샷을 바이트 단위로 대조했다.
- 실제 Windows Go 도구·Rust MSVC로 검증용 앱을 준비했다. Go 입력 1,101개는
  앞선 검증 소스와 같음을 확인하고 같은 네이티브 바이너리를 재사용했다.
- Windows Rust 검사 276개 통과, 기존 opt-in 4개 ignored. 호스트 Rust 전체는
  191개 통과, 기존 ignored 1개다. 링크/junction의 상위 경로를 거부하고 실제
  링크 대상에 쓰지 않는 검사도 각 플랫폼에서 실행했다.
- 최종 Windows staged 앱의 실제 토큰/DB/백업 통합 검사는 37.57초에 통과했다.
  다섯 사례 모두 true, 원본·복원 후 capabilities 200, 백업 113,990 bytes,
  runtime 재사용 true, expiry ok를 확인했다. 새 임시 폴더의 erase 대상들을
  실행 전에 출력하고 소유 범위를 확인했다. 사용자 데이터는 쓰지 않았다.
- 같은 기존 진단 폴더를 다시 넘기면 종료 코드 2로 거부했다. 기존 설정과
  `check.json` 해시가 그대로인 것을 실제 Windows 앱으로 확인했다.
  종료 후 검증 루트 아래 실행 파일의 남은 프로세스는 0개였다.
- Windows의 실제 설치 smoke 래퍼를 fake 효과로 실행한 오프라인 검사 76개
  통과. 토큰 증거 누락·거짓·잘못된 형식과 기존 실패/안전한 정리 계약을 포함한다.
  이 검사는 실제 제품 설치·제거·레지스트리 변경을 실행하지 않았다.
- Python 도구 90개, actionlint, 작업 기록과 `git diff --check` 통과.
  Go/UI 소스는 바꾸지 않아 동일한 전체 검사를 반복하지 않았다. 해당 기반의
  직전 전체 DB 통합 커버리지는 memory 83.64%, crewrun 79.56%로 하한 통과다.

검증 로그·단계 상태·비밀이 없는 JSON 보고서는 별도 로컬 근거 폴더에 보관한다.
실제 토큰, DB 덤프, 사용자 프로필과 빌드 바이너리는 공개 Git 이력에 넣지 않는다.

## 실패와 보강

처음 진단 marker의 Rust 오류 형식 변환이 컴파일에서 드러나 수정했다. 새 경로
계약을 대조하면서 기존 installed smoke가 models 파일을 미리 쓰는 것을 발견해
설정 생성을 진단으로 옮겼다. 경로 보호를 느슨하게 만들지 않았다.

오프라인 검사 추가 과정에서는 PowerShell의 동적 변수 범위로 사례 이름이 검사
항목 이름을 가리는 문제와 빠진 정적 검사 참조 파일을 수정했다. 각 부정 사례는
예상한 토큰 증거 오류로 실패하는지 확인한다. 기존 숫자 형식 부정 사례도 다른
필수 필드 때문에 우연히 실패하지 않도록 유효한 새 필드를 포함했다.

## 한계와 다음 작업

이번 실행은 실제 Windows의 staged 앱과 새 테스트 DB 검증이다. 최종 NSIS
설치/제거, 기존 사용자 프로필 업그레이드, 전원 장애·실제 프로세스 강제 종료,
원격 CI·운영 키/설정 변경, push·PR·공개 릴리스는 실행하지 않았다.
사용자에게 전달한 첫 서명 설치 파일 `2e73b0e`는 바꾸지 않았다.

설치 스크립트의 파일별 덮어쓰기·고정 Sleep과 autostart Run 값 정리 누락은
후속 구현이다. SSH 최초 지문 확인, UI 전량 로딩/모듈화, OpenAPI 계약 강화도
남아 있으므로 전체 공개 평가 개선을 완료했다고 판단하지 않는다.

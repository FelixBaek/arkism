# 2026-10-21 Windows 설치 교체·복구 코어

작업 ID: Task: none (공개 평가 P1-7, 파일별 덮어쓰기와 고정 대기의 대체 기반)

## 이유와 구현 범위

이전 작업은 자동 시작 정리만 연결했다. 현재 제품 NSIS의 파일별 덮어쓰기와
Stop-Process/Sleep은 아직 남아 있다. 교체·복구를 NSIS 분기문에 더 얹지 않고
Windows 전용 `internal/installtxn`으로 분리했다. 이 코어는 아직 NSIS가 호출하지
않으므로 제품 설치 원자성을 해결했다고 판단하지 않는다.

새 payload를 같은 볼륨의 별도 incoming 디렉터리에 복사한다. 경로·크기·SHA256과
빈 디렉터리까지 대조한 다음 기존 프로세스 종료를 요구한다. 기존 전체 폴더를
previous로 옮기고 새 폴더를 기존 설치 위치로 rename한다. 바로가기·제거 등록은
Metadata 인터페이스의 capture/apply/verify/restore 경계로 묶는다. 실제 레지스트리와
바로가기 구현은 후속 작업이며 이번 검사는 임시 파일로 대체했다.

현재 사용자 SID와 설치 경로, 두 payload의 정확한 inventory, metadata checkpoint를
소유권이 확인된 버전 폴더에 기록한다. 버전 폴더는 현재 사용자와 SYSTEM만 접근하는
보호 DACL을 갖는다. 기존 폴더·마커가 다르면 거부한다. 기존 상위 디렉터리는
rename을 막는 핸들로 유지하고, byte-range lock은 동시 교체를 막는다. 기록은
파일 flush와 같은 볼륨 rename으로 갱신한다. 프로세스가 종료되면 OS가 lock을
해제하므로 다음 실행이 복구할 수 있다.

각 rename 전 기록을 남기고 실제 폴더 배치를 함께 대조한다. 완료 전 중단이면
이전 폴더와 metadata를 복원한다. 완료 기록 이후 중단이면 새 버전을 유지한다.
원복에 실패하면 최초 오류와 복구 오류를 함께 남기고 checkpoint를 보존한다.
이미 파일을 복원한 뒤 metadata 복원이 실패한 경우도 재시도할 수 있다. 고친
이력이 없는 파일과 손상된 checkpoint를 추측해 덮어쓰거나 삭제하지 않는다.

프로세스 종료는 이름으로 후보만 찾고 실제 이미지 경로와 열린 프로세스 핸들로
소유 범위를 확인한다. 같은 핸들로 종료와 완료를 기다린 뒤 다시 열거한다.
이름만 같은 다른 경로는 종료하지 않는다. 다른 계정의 검사 불가능한 후보,
종료 실패, 제한 시간 초과는 성공으로 취급하지 않는다. helper 자체가 설치
폴더 안에서 실행 중이면 거부한다. 고정 Sleep을 종료 증거로 사용하지 않는다.

## 실행한 검증

- 실제 Windows SDK Go 도구로 전체 패키지 검사 통과, 하위 사례 53개 통과.
  새 설치/업그레이드에서 단계별 실패·변조·동시 lock·link와 메타데이터 복구
  실패 후 재시도를 확인했다. 기존 버전에 추가된 무관한 파일도 이전 폴더에
  보존된다.
- 자식 프로세스를 실제 종료 코드 77로 끝내 defer를 실행하지 않는 중단 검사
  12개 통과. 복사 완료, 교체 준비, 이전 폴더 이동, 새 폴더 이동, metadata 적용,
  완료 기록 직후를 새 설치/업그레이드 각각에서 확인했다. 전원 장애 검사가 아니다.
- 실제 테스트 실행 파일을 Arkism.exe로 복사해 실행했다. 종료 완료를 열린
  핸들로 확인했고, 다른 경로의 같은 이름 프로세스는 살아 있음을 확인했다.
  이 종료 함수를 실제 폴더 교체와 연결한 사례, 이미 idle인 경우, 잘못된 예산,
  Windows 확장 경로로 실행한 이미지도 통과했다. 제품 앱과 사용자 DB는 실행하지 않았다.
- 위조 SID·설치 경로·ID·단계와 변경된 이전/새 payload는 프로세스 종료 전에
  거부하고 양쪽 파일을 보존한다. source나 상위 경로의 링크도 대상에 쓰지 않고 거부한다.
- Windows 패키지 커버리지 78.8%. Windows GOOS vet, Windows 테스트 바이너리
  컴파일, actionlint, diff 공백 검사 통과. Go 복잡도 검사 통과: 새 함수/closure
  50개의 최대 순환 복잡도 20, 기존 부채 381개에 증가 없음.
- Windows Checks에 실제 패키지 검사와 커버리지 artifact를 추가했다. 원격 CI는
  미실행이며 로컬 실행을 원격 통과로 표시하지 않는다. 다른 OS 앱은 빌드하지 않았다.

## 실패와 보강

첫 테스트 소스의 괄호 누락을 컴파일에서 수정했다. 새 Install 함수의 복잡도가
31로 로컬 게이트에 거부되어 초기 기록·복사 준비·공개·복구 단계로 분리했다.
기준선이나 하한은 느슨하게 바꾸지 않았다. 복구 전에 payload를 검증하도록
보강하여 손상된 이력 때문에 현재 실행 파일을 먼저 종료하지 않게 했다.
경로 별칭 비교도 보강하고 최종 소스를 Windows에서 다시 실행했다.

## 미실행과 다음 구현

실제 제품 NSIS 연결, 검증용 helper의 패키징, 실제 바로가기·HKCU 제거 등록의
소유권 확인·복원, 실제 설치/제거·업그레이드, 운영 프로필과 DB 마이그레이션,
프로세스 트리 강제 종료와 전원 장애, 원격 실행·push·릴리스는 미실행이다.
기존에 전달한 서명 설치 파일도 바꾸지 않았다.

다음 작업은 helper를 설치 폴더 밖에 추출하고, 인증된 패키지의 inventory와
NSIS가 생성한 제거 파일을 연결하는 것이다. Metadata 구현이 기존 설치의
소유권을 확인하고 바로가기·제거 등록까지 같은 트랜잭션에 넣어야 한다.
그 뒤 실제 설치/업그레이드 실패 검증을 통과시켜야 한다.

기존·실패 폴더는 이 코어가 재귀 삭제하지 않고 버전별로 보존한다. 최종 제품에는
정확한 manifest로 소유권을 증명한 과거 프로그램의 보존 개수 제한이 더 필요하다.
기록 없이 생성되다 중단된 예약 폴더나 손상된 이력은 자동 추측 정리를 거부하므로
수동 복구가 필요하다. 검사 후 사용자가 다시 시작한 비협력적인 과거 앱의 실행을
막거나 동일 사용자 공격자의 모든 경로 교체 경쟁을 차단한다고 보장하지 않는다.

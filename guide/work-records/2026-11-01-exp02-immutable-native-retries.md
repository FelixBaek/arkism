# EXP02 immutable native retry execution

Task: EXP-02 / EXP-03 (#153)
Research: Execution/analysis evidence binding, not empirical efficacy or research acceptance.
Design: Add separately versioned v3 producer, dispatch and projection sidecars while preserving frozen original RunPlan/RunIndex DTOs. Predeclare attempt IDs/order, exact original argv, exclusive work namespace and per-attempt/global deadlines. Reserve a fresh journal and work root before native dispatch. Atomically move each child output into a deterministic attempt archive using Linux RENAME_NOREPLACE. Partial outputs survive killed/reaped children without becoming successful quality. Native completed output is verified both before and after relocation; the projector accepts only its exact declared attempt path. Costs/statuses remain per physical attempt; primary observations use the first comparable completed result with predeclared-order tie break.
Relation: partial
Deviation: Linux atomic directory moves are required for this new archive protocol. Missing platform support rejects before dispatch; runtime filesystem move errors preserve output and stop further execution. Prior v1/v2 behavior remains available. Archive bytes and actual argv are not rewritten; no successful process receipt is synthesized from an output directory.
Why: The original execution recorder allowed one attempt per job. Reusing the output path without immutable archives would overwrite previous results or prevent retries after a timeout that left partial files. Selecting later duplicates would also inflate or bias the primary analysis.

## Observed failures and corrections

The first functional test correctly rejected the missing v3 request protocol before implementation. The initial timeout run then showed a partial output directory, so the next retry stayed unrun. The recorder now owns a freshly reserved work directory and archives that partial output after child termination. The failed attempt remains timeout; it is never converted to completed because files exist. All initial failure logs are retained privately. No expected outcome, assertion or original source event was removed.

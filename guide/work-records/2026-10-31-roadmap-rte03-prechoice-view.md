# RTE-03 routing decision sees a re-checked work view read before the choice

Task: RTE-03 (#155)
Research: none
Design: When a crew run names a work checkpoint, the runner now reads it once before asking for a model. The same read gives the rendered context every fallback receives and a metadata-only view (checkpoint id, revision and updated_at, source ref identities, archive history count as known_empty or observed) sent as the optional `view` of `POST /v1/routing/decide`. The server re-reads that checkpoint with the caller token through the normal work checkpoint read (permission, source ref currentness, deletion and transaction fences, audit) after the candidates are known, and returns `view_hash` (SHA-256 of its own re-read view) only when every field matches; a later revision or a wrong history claim is 409, another scope keeps the existing 404. A failed read stops the run before any choice, so it is never an empty history, and a view the server did not confirm stops the run too. Model choice itself is unchanged, the hook path keeps rendering without the view, and the gateway is untouched.
Relation: extends
Why: RTE-03 needs routing features built only from observations available before the decision, replayable for the same legal snapshot, and fenced against stale, deleted or foreign references, without sending work bodies to the decision.
Verified: On an own disposable PostgreSQL, `go test ./internal/memory -run 'TestPostgresRoutingDecideRechecksTheWorkViewReadBeforeTheChoice|TestRoutingPrechoiceView|TestPostgresWorkCheckpointHooksReadCurrentState|TestWorkCheckpoint|TestRouting'` passed 107 in plain and 107 under race with no failure or skip. The PostgreSQL test drives the real runner read (`host.WorkHookContextView`) and decide over HTTP: the same view replays to the same hash, no decide request carries the checkpoint goal or title, a revision saved after the read is 409, a fresh read gets a new hash and another scope is 404. The offline test also covers a wrong history claim, a changed ref or updated_at (409), unknown history, bad counts, revision 0, missing time and bad id (400), deleted source evidence (no hash) and a token that may route but not read work (403). Crew tests show the read happens before decide, a failed read makes no decision and runs nothing, an unconfirmed view runs nothing, every fallback gets the same context and the routed result carries view_hash. `go test -race` for internal/host, crew, gateway and capture passed, as did `go vet`, gofmt on changed lines, `tools/check_openapi.py`, `tools/update_api_contracts.py --check` and the complexity gate. An independent model review first rejected (time check without skew, audit before eligibility); after the fixes a second pass accepted with low-severity notes.
Limits: The view is not the unaccepted SYS approved-view contract and makes no claim of reader inclusion; related memories in the rendered context stay separate direct-evidence reads outside the view. Token estimates and tokenizer measurements are not part of the view. A positive `observed` history was exercised only in the runner unit test, not end to end. Several server replicas with clocks more than 5 s apart could refuse a current view. The gateway does not send views. The full local check and golangci-lint were not run here (lint runs in CI). No product build, deploy or merge was done.

## 한국어 작업 기록

제목: 라우팅이 고르기 전에 읽은 작업 상태를 서버가 다시 확인
이유: RTE-03은 결정 전에 있던 관찰만으로 라우팅 특징을 만들고, 같은 합법 스냅숏은 같은 결과로 재현되며, 낡거나 삭제됐거나 다른 범위인 참조는 막혀야 한다. 작업 본문은 결정에 보내지 않는다.
검증: 전용 임시 PostgreSQL에서 라우팅·작업 체크포인트 시험 107개가 plain과 race에서 모두 통과했고 실패·skip은 0이었다. PG 시험은 실제 runner 읽기와 HTTP decide로 같은 view는 같은 해시, decide 요청에 목표·제목 없음, 읽은 뒤 저장된 revision은 409, 새로 읽으면 새 해시, 다른 범위는 404임을 확인했다. 오프라인 시험은 틀린 기록 주장·바뀐 참조·시각(409), unknown·잘못된 개수·revision 0·시각 없음·잘못된 id(400), 삭제된 출처(해시 없음), 작업 읽기 권한 없는 토큰(403)을 덮는다. crew 시험은 읽기가 decide보다 먼저이고, 읽기 실패면 고르지도 실행하지도 않으며, 서버가 확인하지 않은 view도 실행하지 않고, 모든 대체 모델이 같은 맥락을 받고 결과에 view_hash가 남음을 확인했다. host·crew·gateway·capture race 시험, go vet, 바뀐 줄 gofmt, OpenAPI 검사, API 계약 검사, 복잡도 검사도 통과했다. 독립 모델 검토는 처음에 반려(시계 오차 없는 시각 검사, 적격성 전 감사)했고 수정 뒤 2차에서 수용했다.
한계: 이 view는 아직 승인되지 않은 SYS approved-view 계약이 아니며 실제 독자 포함을 주장하지 않는다. 렌더된 맥락의 관련 기억은 view 밖의 별도 읽기다. 토큰 추정값과 토크나이저 측정값은 view에 없다. observed 기록은 runner 단위 시험에서만 확인했다. 시계가 5초 넘게 다른 서버 복제본은 현재 view를 거부할 수 있다. Gateway는 view를 보내지 않는다. 전체 로컬 검사와 golangci-lint는 돌리지 않았다(lint는 CI). 제품 빌드·배포·병합은 하지 않았다.

# Run bounded dynamics measurements after parallel test groups

Task: PR526 CI, SYS-05/06 measurement validation
Research: Engineering diagnosis of test scheduling; no product performance or effect claim.
Design: Extract the three real PostgreSQL measurement/overload tests from parallel batches and defer the complete daemon regression package as one ordered batch. Execute each once after all sibling groups and other-package tests finish. Use the same compiled binary, race/integration configuration, count, timeout and coverage directory.
Relation: adapted
Deviation: Only test scheduling changes. The worker's one-second fixture budget, production bounds, assertions, fixtures and existing rerun list are unchanged. A serial failure remains a gate failure and is not retried.
Why: CI failed worker rounds and overload drains with dependency_unavailable. Independent contention tests reproduced all three failure signatures with raw PostgreSQL timeout errors and an expired worker context; sibling test work competes for the same CPU quota. A later same-source CI run also failed the daemon off/shadow test because its settled shadow observation was snapshot_unavailable. A final cache generation alone does not guarantee freshness when the worker is stopped and the HTTP searches take time.
Verified: On a dedicated disposable PostgreSQL, each original test passed five sequential runs with genuine restricted LOGIN, 15 passes and zero failures/skips. Contention traces reproduced the deadline errors without altering timers. One actual committed-apply/lost-reply probe confirmed that a joined revision_conflict can arise from correct lease fencing without duplicate application. The original daemon test passed alone under race. A private controlled 1.1-second delay after settling reproduced the same failed observation: cached and durable generation were both12, context was live, and age1,423,614,000ns exceeded the unchanged1,000,000,000ns freshness limit. This proves that expiry can cause the symptom, not that the original CI took that exact branch. The corrected scheduler regression suite passed seven tests covering slot exclusivity, disjoint exact-once selection, phase ordering, full daemon inventory in one batch, exclusion from the remaining packages, inclusion of its third coverage directory, failure propagation and no serial retry. The integrating reviewer reran all seven successfully; earlier overlapping scheduler checks are not added together. Temporary DBs, roles and clients were zero before the private cluster was stopped and removed.
Limits: Original CI lacks raw PostgreSQL error details, so its precise failing SQL and joined-conflict cause are not proven. The scheduling change removes this invocation's sibling competition; it does not reserve the whole host against other CI runs or vet processes. Fresh complete CI acceptance remains required. No product build, deployment, provider call or operating-data access.

제목: 동적 기억 측정·daemon 검사를 병렬 그룹 뒤에 실행
이유: CPU 경쟁에서 1초 작업 제한이 만료되어 CI와 같은 작업·drain 오류를 재현했다.
검증: 실제 임시 PostgreSQL의 원 검사3개를 각각5회 실행해15회가 통과했다. 부하에서 시간 초과를 재현하고 실제 커밋 후 응답 유실의 중복 방지도 확인했다. 별도 daemon 단독 race는 통과했고, 정지 후1.1초 지연 반례에서는 캐시·DB 세대가 같아도 기존1초 유효기간을 넘겨 같은 실패를 재현했다. 원 CI의 정확한 분기를 확정한 것은 아니다. 전체 daemon 검사를 순서 그대로 한 번 실행하고 coverage에 합산하는 스케줄러 회귀7개를 통합 검토자도 통과했으며 임시 DB·역할·연결 정리를 확인했다.
한계: 원 CI의 정확한 SQL·추가 충돌 원인은 단정하지 않는다. 새 전체 CI가 필요하고 다른 실행의 CPU 독점까지 보장하지 않는다. 제한 시간·재시도·판정 기준은 유지한다. 제품 빌드·배포 없음.

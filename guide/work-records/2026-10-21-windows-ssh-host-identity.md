# 2026-10-21 Windows SSH 서버 지문 확인

작업 ID: Task: none (첨부 Arkism 저장소 평가 P1-7, SSH 최초 지문 표시·pin 저장)

## 이유와 변경

기존 `accept-new` 접속은 최초 접속 서버 키를 사람이 비교하지 않고 저장했다.
인증 없는 대상 키 수집, 지문 확인 창, 명시적 승인과 독립 pin 저장을 연결한다.
앱 연결·연결 시험·Git·스킬 실행과 Windows 에이전트에 동일한 pin을 적용한다.
키 변경은 인증 전에 차단하며, 재확인 창에 이전·새 지문을 함께 표시한다.
승인 challenge는 5분·일회용이고, 중간 승인 변경·만료·취소를 거부한다.
Windows 저장소는 사용자·SYSTEM 전용 보호 ACL을 확인한다. 기존 `.ssh` 파일은
바꾸지 않는다. 기존 Windows Job 소유권 경로로 SSH 하위 프로세스를 관리한다.

UI는 기존 확인 창·제품 토큰을 사용한다. 기본 초점은 취소이며 체크박스 확인
전에는 승인할 수 없다. Escape·Enter 취소·키보드 승인·동시 요청·오래된 승인을
실제 Chromium에서 확인한다. 영문 사전에도 새 경고를 추가한다.

Windows 검사 중 기존 테스트의 실제 앱 프로필 참조, JSON 경로 이스케이프,
POSIX 권한 비트 가정과 경로 구분자 가정을 발견해 테스트를 격리·수정했다.
이 변경을 실행하지 않은 검증의 통과 근거로 사용하지 않는다.

## 검증

- 실제 Windows x64 release 기본 검사: 208 + 70 + 19 = 297개 통과,
  실패 0개, opt-in 5개 ignored. 이 중 새 실제 OpenSSH 검사를 별도로 실행해
  1개 통과했다. 기존 통합 바이너리가 코어 검사를 포함하므로 297을 서로 다른
  시나리오 수로 해석하지 않는다. 나머지 hosted 전용 opt-in은 실행하지 않았다.
- 실제 OpenSSH·새 loopback SSH 서버: 미승인·취소 상태 거부, 대상 인증 키 제시
  0회, 승인한 실제 SHA256 지문·별칭·비기본 포트 일치, 공백·퍼센트 포함 경로,
  승인 뒤 실제 개인 키 인증과 응답, 서버 키 교체 시 인증 전 차단, 이전·새 지문
  재확인, 명시적 교체 후 성공, 기존 pin이 몰래 교체되지 않음을 확인했다.
- Windows `go test ./internal/host/capture` 전체 통과(최종 실행 31.980초).
  새 에이전트 검사는 pin 누락·변조·외부 경로·알고리즘 변경 거부, 실제 키 파싱,
  경로 quoting/percent escaping, 명시적 CLI의 strict 검증을 포함한다.
- Windows production 앱 컴파일 통과. 기존 production 경고 17개는 남아 있다.
  전용 폴더 실행 파일의 잔여 프로세스 0개를 별도로 확인했다.
- 실제 로컬 Chromium의 지문 창 8개 시나리오 통과: 기본 초점과 Enter 취소,
  Escape 취소, 키보드 승인·초점 복귀, 키 변경 취소·명시적 교체, 동시 요청
  병합, stale 승인 거부, 360px/글꼴 확대에서 가로 넘침 없음. 실제 스타일로
  렌더링한 창도 확인했다. 전체 앱 잠금→SSH→기억 승인→삭제 E2E는 아니다.
- 기존 UI 테스트 파일 13개 통과. i18n 정적·템플릿 누락 0개.
  Better Design 로컬 CSS 검사 최종 발견 0개. 초기 px 지적은 제품 토큰·rem으로
  수정했다. 코드 검사와 실제 브라우저 검증은 별도로 수행했다.
- Go 복잡도 게이트 통과: 새 검증 함수는 최대 10, 기준 20 이하.
  actionlint, 관련 rustfmt, Node 구문, diff 검사 통과. Windows CI에 같은
  에이전트·네이티브 SSH 검사를 추가했으며 원격 CI 실행은 아직 하지 않았다.

첫 Windows Go 검사는 기존 테스트의 실제 앱 프로필 참조, JSON 경로 두 곳,
POSIX mode 가정과 경로 구분자 차이로 실패했다. 이를 수정한 뒤 전체를 다시
실행해 통과했다. 초기 Rust 오류는 에러 변환의 `String` 타입을 명시해 고쳤다.
초기 브라우저 검사에서 Enter 취소가 동작하지 않는 문제를 고친 뒤 8개를
다시 통과했다. 실패한 실행을 성공 근거에 섞지 않았다.

처음 전체 소스 전송은 자동 승인 검토가 민감한 자료 유출 위험으로 거부했다.
대신 코드·테스트 파일을 명시하고 gitleaks 누락 0건을 확인한 22개 파일만
전송하는 방식이 승인됐다. 이전 Windows 소스의 소유 표식·archive 해시와
각 원본 파일 해시를 확인하고 새 전용 폴더에서 검증했다.

최종 overlay SHA256:
`0f095503be7f852df9b04a89f4d8d11e3f2b4036e71215ccfd5f818f08b8f4bc`.
검증된 이전 Windows 소스 archive SHA256:
`38a511b3fb818c22b944822afb3b5551d5483bc9f7efcdc1d3a3dab5b88853e8`.
전송 이후 해당 22개 파일의 로컬 hash가 그대로임도 확인했다. 실행 로그,
source manifest, 검사·잔여 프로세스 JSON은 로컬 빌드 근거 폴더에 보관했다.

## 한계

SSH `none` 요청은 대상 사용자 이름을 보낼 수 있다. 사용자 SSH 설정과
ProxyCommand/ProxyJump는 신뢰 경계이며 점프 서버에는 설정한 인증이 가능하다.
사람의 별도 지문 비교 자체를 자동 검증했다고 주장하지 않는다.
실제 서버 접속·실제 앱 설치/제거·공개 릴리스는 이 작업에서 실행하지 않는다.

ProxyJump·다양한 사용자 SSH 설정 조합과 실제 제품 전체 연결 E2E는 이번
회귀 검사의 실행 범위가 아니다. 기존에 전달한 `4ac870f` 설치 파일에는
이번 변경이 들어 있지 않다. 새 설치 패키징·서명·공개 배포는 별도 단계다.
UI 모듈 분리·지연 번역 로드·목록 페이지 처리, OpenAPI 계약 검증과 원격
저장소 보호 설정 적용 등 첨부 평가의 나머지 개선을 완료했다고 주장하지 않는다.

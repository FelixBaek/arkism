# RTE-05 routed step that may have changed things is never run again on a fallback

Task: RTE-05 (#155)
Research: none
Design: A routed crew step tries its candidate models in order. Before this change any failure handed the same task to the next model, so a write step that timed out or hit a limit after its CLI had already edited files or run commands could be run a second time by another model. The fallback loop now lives in `tryRoutes`, and `mayHaveChanged` stops it when the failed attempt may write (write or full access, including the default) and its CLI had started. Only proven no-run cases still fall over: a CLI that was not found, an account refused before the start (now reported with `duration_ms` 0, while any started run reports at least 1), a request refused before it was sent (a crew error), and any read-only step. A chat completion has no tools, so its result carries an internal marker that only the routing loop reads (`runAttempt`); `runNode` and the loop both drop it, so no output gains a field. A stop is shown as `routed.stopped = "effect_unknown"`, which means the last attempt that ran may have changed things (it is also set when that attempt was the last candidate); every attempt is still reported, and model choice, order and the once/research paths are unchanged.
Relation: extends
Why: RTE-05 needs fallback to respect side effects: an attempt whose effect is unknown must not be repeated by another model, while refusals proven to happen before any work keep the existing fallback.

Call-boundary constraints:

| Boundary | Retry or fallback | Bound | Unknown state |
|---|---|---|---|
| Gateway lanes | lane slot, 429 before the response starts | not changed or re-tested here | existing guard: no retry after the response starts |
| Meeting | overBudget stops further turns | not changed or re-tested here | not changed |
| Crew routed step | next candidate in order | at most the candidate list; each attempt has its own timeout, so wall time can reach N times it | write/full/default step that started: stop, `routed.stopped` |
| Crew read or once step, chat call | next candidate in order | same | no tools: falls over |

Rollout and rollback: the change is local to the crew runner and adds one output field, but it changes behaviour: a default or write-access step that fails after its CLI started (timeout, 503, a 429 exit) used to fall over and now stops, so for most routed write steps fallback now covers only refusals before the start. The safety rule applies to every policy, so there is no flag. Rolling back is reverting this commit; the decide API, stored data and the gateway are untouched, so no migration or flag is needed.

Verified: `go test -race ./internal/host/crew/ ./internal/host/` passed, as did `go vet`, gofmt on changed files and the complexity gate. The new table test covers write, full and default access with a timeout, a CLI 429 exit, a mid-run limit and a 503 (stop after one run, `routed.stopped` set) against cli_not_found, a pre-start limit, a read step and a once step (fall over), plus a chain that stops on the second model and an all-refused list that tries every model with no stop marker. A chat call falls over and its marker never reaches a runNode result. Mutations that drop the start-time check, force the stop off, remove the 1 ms floor or leak the marker each fail a test. An independent model review first rejected (mid-run limits still fell over, an ambiguous custom CLI exemption, a dead branch); later passes asked for the chat path, number types and the documented limits above; after those fixes a fourth pass accepted with low and medium notes recorded here.
Limits: A CLI that exits with a 429 after it started now stops a write step instead of falling over, since an exit does not prove that no tool ran. User-configured `callAI` retries in the crew run nodes are outside this card's paths and can still repeat a failed step. The call report carries no stop marker; only the routed result does, and whether meeting or workflow retry code honours `routed.stopped` was not checked. No group or handoff routed case was added; both go through the same loop. Not implemented here: a shared total time, call or tool budget across fallbacks; continuation model pinning and its provider-mismatch case; concurrency reservation and reconciliation across fallbacks. The gateway lane and meeting rows above were not changed or re-tested in this change. Failures relayed from an agent-runner backend are classified only by their error and duration, so a missing duration stops a write step. A pre-start quota refusal now reports 0 ms latency and a started run at least 1 ms; consumers of `latency_ms` were not audited. The full local check and golangci-lint were not run here (lint runs in CI). No product build, deploy or merge was done.

## 한국어 작업 기록

제목: 무언가 바꿨을 수 있는 단계는 대체 모델로 다시 돌리지 않음
이유: RTE-05는 대체 실행이 부작용을 존중해야 한다. 효과를 모르는 시도는 다른 모델이 되풀이하면 안 되고, 일을 시작하기 전에 거절된 경우만 기존처럼 넘어간다.
검증: 채팅 호출은 도구가 없어 넘어가고 그 내부 표시는 결과 밖으로 나가지 않는다. crew·host 패키지 race 시험, go vet, 바뀐 파일 gofmt, 복잡도 검사가 통과했다. 새 표 시험은 쓰기·전체·기본 권한의 시간 초과, 시작 뒤 429 종료, 실행 중 한도, 503이 한 번만 돌고 멈추며 stopped가 남는 것과, CLI 없음·시작 전 한도·읽기 단계·once 단계는 넘어가는 것을 확인한다. 두 번째 모델에서 멈추는 연쇄와 모두 거절된 경우도 덮는다. 시작 시각 검사 제거, 멈춤 강제 해제, 1ms 하한 제거, 내부 표시 누출 변이는 모두 시험이 잡았다. 독립 모델 검토는 처음 반려(실행 중 한도가 넘어감, custom 예외 모호, 죽은 분기)했고, 이후 채팅 경로·숫자 형식·한계 기록 지적을 고친 뒤 4차에서 수용했다(남은 낮은·중간 지적은 한계에 적음).
한계: 시작 뒤 429로 끝난 CLI는 이제 쓰기 단계를 멈춘다. 종료만으로 도구가 안 돌았다고 볼 수 없어서다. crew run 노드의 사용자 설정 callAI 재시도는 이 카드 경로 밖이라 실패 단계를 다시 돌릴 수 있다. 호출 보고에는 멈춤 표시가 없고 routed 결과에만 있으며, meeting·workflow 재시도 코드가 routed.stopped를 따르는지는 확인하지 않았다. 시작 뒤 실패한 기본·쓰기 단계는 이제 넘어가지 않으므로 대부분의 라우팅 쓰기 단계에서 대체 실행은 시작 전 거절에만 남는다. group·handoff 라우팅 경우는 시험을 추가하지 않았다. 대체 실행 전체의 공통 시간·호출·도구 예산, continuation 모델 고정과 제공자 불일치 경우, 동시성 예약·정산은 구현하지 않았다. 표의 Gateway lane·meeting 줄은 이번에 바꾸거나 다시 시험하지 않았다. 외부 실행기 결과는 오류와 시간만으로 판정해 시간이 없으면 쓰기 단계를 멈춘다. 시작 전 한도 거절은 지연 0ms, 시작한 실행은 최소 1ms로 보고되며 latency_ms 사용처는 점검하지 않았다. 전체 로컬 검사와 golangci-lint는 돌리지 않았다(lint는 CI). 제품 빌드·배포·병합은 하지 않았다.

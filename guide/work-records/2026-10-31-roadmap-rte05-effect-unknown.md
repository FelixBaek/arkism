# RTE-05 routed step that may have changed things is never run again on a fallback

Task: RTE-05 (#155)
Research: none
Design: A routed crew step tries its candidate models in order. Before this change any failure handed the same task to the next model, so a write step that timed out or hit a limit after its CLI had already edited files or run commands could be run a second time by another model. The fallback loop now lives in `tryRoutes`, and `mayHaveChanged` stops it when the failed attempt may write (write or full access, including the default) and its CLI had started. Only proven no-run cases still fall over: a CLI that was not found, an account refused before the start (now reported with `duration_ms` 0, while any started run reports at least 1), a request refused before it was sent (a crew error), and any read-only step. A chat completion has no tools, so its result carries an internal marker that only the routing loop reads (`runAttempt`); `runNode` and the loop both drop it, so no output gains a field. A stop is shown as `routed.stopped = "effect_unknown"`, which means the last attempt that ran may have changed things (it is also set when that attempt was the last candidate); every attempt is still reported, and model choice, order and the once/research paths are unchanged.
Relation: extends
Why: RTE-05 needs fallback to respect side effects: an attempt whose effect is unknown must not be repeated by another model, while refusals proven to happen before any work keep the existing fallback.

Call-boundary constraints:

| Boundary | Retry or fallback | Bound | Unknown state |
|---|---|---|---|
| Gateway lanes | a pick that answered 429 rests and later requests try the next member | not changed; `TestGatewayRestsAModelAfter429` (lanes_test.go) only checks the rest and the probe after it | not changed |
| Gateway group | a rejection before the response starts moves to the next member | not changed; `TestProviderAPIGroupFailoverOnRejectionAndServerError` | a response that already started is never replayed on another member; a continued conversation is pinned (`pinGroup`, gateway.go:1917-1942, called at gateway.go:1862; a pin that no member matches is a 409 `conversation_mismatch`, gateway.go:1863) |
| Meeting | overBudget stops further turns | not changed; `TestBudgetWaitsThenGoesOnAfterApproval` | not changed |
| Crew routed step | next candidate in order | at most the candidate list, which crew code does not cap; the step timeout (`timeout_s`, else the step default, else the agent-runner default for a runner step) is one wall-time budget for the chain: a later attempt gets only the time left, none starts under 1 s left (`routed.stopped = "budget_spent"`) | write/full/default step that started: stop, `routed.stopped = "effect_unknown"` |
| Crew read or once step, chat call | next candidate in order | same | no tools: falls over |

Rollout and rollback: the change is local to the crew runner and adds one output field, `routed.stopped`, with two values, but it changes behaviour twice. A default or write-access step that fails after its CLI started (timeout, 503, a 429 exit) used to fall over and now stops (`effect_unknown`), so for most routed write steps fallback now covers only refusals before the start. Every routed step, read, once and chat steps included, now shares one time budget: a later attempt gets only the time left instead of a fresh timeout, and a step whose budget is spent stops with `budget_spent`. A consumer that reads any `stopped` value as `effect_unknown` would misread `budget_spent`; no consumer was checked. `tried` lists every attempt made, pre-start refusals included, and never a skipped candidate. The safety rule applies to every policy, so there is no flag. Rolling back is reverting this commit; the decide API, stored data and the gateway are untouched, so no migration or flag is needed.

Budget change (added after the effect_unknown change above): the step timeout is now one wall-time budget shared by the fallback chain (`tryRoutes`, `chainBudget`; the clock `routeNow` is replaceable in tests). The first attempt keeps its spec; a later attempt gets `timeout_s` set to the time left, rounded up to whole seconds, so it can overrun the deadline by under 1 s. When under 1 s is left the loop stops with `routed.stopped = "budget_spent"` and starts no attempt; `routed.id` and the result are those of the previous attempt, and `tried` lists every attempt made, pre-start refusals included, never a skipped candidate. A failed write attempt that started is still `effect_unknown`, which is checked first. The budget starts inside `tryRoutes`: the decide call and the work-context read before it are not counted. An invalid, zero or negative, or overflowing (too large to round up within int64 nanoseconds) `timeout_s` gets no budget, because `runLocalNode` does not refuse it (a negative one just times out at once), so each attempt keeps its own value as before. A runner step without `timeout_s` uses the runner default (`backendTimeout`, backend_run.go:40 and :255) as its budget, not the 900 s step default. The card's shared total tool, call and time limit is met for time only: the call count is bounded only by the candidate list, which crew code does not cap, and the node result exposes no tool count. Not checked beyond reading: that every run path honours an overridden `timeout_s`; by reading, the local path (runnode.go:302 reads it, :333 passes it to the chat call, :353 to the CLI spawn) and the runner path (backend_run.go:251 reads it, :316 sends it as `limits.timeout_s`) do.

Verified, effect_unknown change (accepted at an independent fourth review): `go test -race ./internal/host/crew/ ./internal/host/` passed, as did `go vet`, gofmt on changed files and the complexity gate. The table test covers write, full and default access with a timeout, a CLI 429 exit, a mid-run limit and a 503 (stop after one run, `routed.stopped` set) against cli_not_found, a pre-start limit, a read step and a once step (fall over), plus a chain that stops on the second model and an all-refused list that tries every model with no stop marker. A chat call falls over and its marker never reaches a runNode result. Mutations that drop the start-time check, force the stop off, remove the 1 ms floor or leak the marker each fail a test. An independent model review first rejected (mid-run limits still fell over, an ambiguous custom CLI exemption, a dead branch); later passes asked for the chat path, number types and the documented limits; after those fixes a fourth pass accepted with low and medium notes recorded here.

Verified, budget change (an independent review rejected the first version and asked for the cases below; a second pass accepted with two low notes, the round-up edge of the overflow guard and the rollout text, both fixed afterwards and not re-reviewed): `go test -race ./internal/host/crew/ ./internal/host/` (host with `-count=1`) passed, as did `go vet ./internal/host/crew/`, gofmt on routing.go and routing_budget_test.go, and `go run ./tools/complexity` (exit 0; gofmt still lists the older crew_test.go and backends_test.go, not touched here). `TestFallbackChainSharesOneTimeBudget` (routing_budget_test.go) checks the timeout each attempt gets and the stop: a 60 s budget gives 60, 35 and 10 s; 50 s with 45 s spent per attempt gives 50 and 5 s and then stops; 0.5 s and 0.999 s left stop; exactly 1 s left runs with 1 s; 1.2 s left runs with 2 s; a spent budget runs only the first; no `timeout_s` uses the step default; a runner step without `timeout_s` uses the runner default; an invalid, negative and overflowing `timeout_s` are not overridden and all three models are tried. `TestBudgetStopNeverHidesAnUnknownEffect` checks that a started write step that fails after spending the budget is `effect_unknown`, and a read step that times out and spends it is `budget_spent` with the first attempt's id, result and `tried`. Budget mutations run, each failing these tests and restored from a copy: stop check off, timeout override removed, round up changed to round down, the zero-or-negative guard removed, the runner default removed, the overflow guard removed, the stop threshold changed from 1 s to 0, and the overflow guard put back to MaxInt64/1e9 (caught by the round-up edge case, 9223372036 s). Not run as a mutation: swapping the order of the effect_unknown and budget checks.
Gateway and meeting rows (no change here, existing tests only), run with `go test -race -run '<names>' -v ./internal/host/gateway/` and `./internal/crewrun/`, all PASS: `TestGroupContinuationPinsModelAndExpiredIDsNeverFallBack` and `TestMessagesGroupContinuationIsolatedAndExpiredIDsNeverFallBack` (a continued request with another group, another caller or the bare model gets 409 and is not routed; an expired continuation does not fall back; the continuation's target list is only the pinned model; a failure of a started run is reported once and not replayed); `TestCoreNativeGroupContinuationAcceptsAliasAndNeverChangesProvider` (a continuation whose decision lists another provider first reuses the one live run on the pinned Anthropic model, with no auth call or other request); `TestProviderAPIGroupFailoverOnRejectionAndServerError` (a 429 or 500 before the response moves to the next member, for chat, messages and responses); `TestProviderAPIStartedTruncationNeverReplaysOrSucceeds` and `TestGoogleCrossConfirmedRejectionCanFallBackButStartedTruncationCannot` (a response cut after it started is not replayed on another member and has no success marker; a literal 503 after partial output cannot be sent once headers are out, so a cut stream stands for it); `TestGatewayRestsAModelAfter429` (a 429 rests the pick, the next request goes to the backup, and a probe after the rest returns to it); `TestBudgetWaitsThenGoesOnAfterApproval` (an over-budget member makes the meeting wait with only the brief turn recorded, and the poller leaves it alone until approval). `TestClaudeMismatchesDoNotGenerateOrDestroyWaitingRun` is not cited: it checks body and owner mismatches, not a provider mismatch. Model-and-provider pinning is read from `pinGroup` (anthropic candidates matched by model, Google by the full id).
Limits: A CLI that exits with a 429 after it started now stops a write step instead of falling over, since an exit does not prove that no tool ran. User-configured `callAI` retries in the crew run nodes are outside this card's paths and can still repeat a failed step. The call report carries no stop marker; only the routed result does, and whether meeting or workflow retry code honours `routed.stopped` was not checked. No group or handoff routed case was added; both go through the same loop. Time is the only shared budget: no shared tool or call count exists (the node result does not expose one) and the attempt count is bounded only by the candidate list, which crew code does not cap, so the card's shared tool/call/time limit is only partly met. Rounding up can overrun the deadline by under 1 s, the decide call and the work-context read are outside the budget, and a started attempt can still use all the time left. Concurrency reservation and reconciliation across fallbacks stay unimplemented. Gateway and meeting behaviour were not changed and no new gateway or meeting test or mutation was added. Failures relayed from an agent-runner backend are classified only by their error and duration, so a missing duration stops a write step. A pre-start quota refusal now reports 0 ms latency and a started run at least 1 ms; consumers of `latency_ms` were not audited. The full local check and golangci-lint were not run here (lint runs in CI). No product build, deploy or merge was done.


## 한국어 작업 기록

제목: 무언가 바꿨을 수 있는 단계는 대체 모델로 다시 돌리지 않음
이유: RTE-05는 대체 실행이 부작용을 존중해야 한다. 효과를 모르는 시도는 다른 모델이 되풀이하면 안 되고, 일을 시작하기 전에 거절된 경우만 기존처럼 넘어간다.
검증: (effect_unknown 변경, 독립 검토 4차 수용) 채팅 호출은 도구가 없어 넘어가고 내부 표시는 결과 밖으로 나가지 않는다. crew·host race 시험, go vet, 바뀐 파일 gofmt, 복잡도 검사가 통과했다. 표 시험은 쓰기·전체·기본 권한의 시간 초과, 시작 뒤 429 종료, 실행 중 한도, 503이 한 번만 돌고 멈추는 것과, CLI 없음·시작 전 한도·읽기·once 단계가 넘어가는 것, 두 번째 모델에서 멈추는 연쇄, 모두 거절된 경우를 덮는다. 시작 시각 검사 제거, 멈춤 강제 해제, 1ms 하한 제거, 표시 누출 변이는 모두 시험이 잡았다.
검증: (예산 변경, 독립 검토 1차 반려 뒤 보완, 2차 수용. 2차의 낮은 지적 둘(넘침 보호의 올림 경계, 배포 설명)은 그 뒤 고쳤고 다시 검토하지 않음) crew·host race 시험(host는 -count=1), crew go vet, routing.go·새 시험 gofmt, 복잡도 검사(exit 0)가 통과했다(예전 crew_test.go·backends_test.go는 gofmt 목록에 남아 있고 이번에 건드리지 않았다). 새 시험은 시도마다 받는 timeout과 멈춤을 확인한다: 60초 예산은 60·35·10초, 50초에 시도마다 45초면 50·5초 뒤 멈춤, 0.5초·0.999초 남으면 멈춤, 정확히 1초 남으면 1초로 실행, 1.2초 남으면 2초, 소진이면 첫 시도만, timeout_s 없으면 step 기본값, 실행기 단계는 실행기 기본값, 잘못된·음수·넘치는 timeout_s는 덮어쓰지 않고 세 모델 모두 시도. 시작한 쓰기 단계가 예산을 쓰며 실패하면 effect_unknown이고, 시간 초과로 예산을 쓴 읽기 단계는 첫 시도의 id·결과·tried와 함께 budget_spent다. 돌린 예산 변이(복구 후 각각 시험 실패 확인): 멈춤 검사 끔, timeout 덮어쓰기 제거, 올림을 내림으로, 0 이하 보호 제거, 실행기 기본값 제거, 넘침 보호 제거, 멈춤 기준 1초를 0으로, 넘침 보호를 MaxInt64/1e9로 되돌림(올림 경계 9223372036초 경우가 잡음). effect_unknown과 예산 검사의 순서를 바꾸는 변이는 돌리지 않았다.
검증: (Gateway·meeting, 이번에 바꾸지 않음, 기존 시험만 -race -run -v로 실행해 모두 PASS) 그룹 continuation 시험 둘(다른 그룹·호출자·모델은 409이고 라우팅 안 함, 만료는 대체 안 함, 후보는 고정된 모델뿐), 코어 네이티브 continuation 시험(다른 제공자가 앞선 결정이어도 고정된 Anthropic 실행 하나를 재사용), 그룹 대체 시험(응답 전 429·500은 다음 후보로), 시작 뒤 끊김 시험 둘(다른 후보로 재실행하지 않고 성공 표시 없음; 헤더 이후 503은 보낼 수 없어 끊긴 스트림으로 대신함), TestGatewayRestsAModelAfter429(429 뒤 쉬고 쉼이 끝나면 다시 탐침), TestBudgetWaitsThenGoesOnAfterApproval(예산 초과면 brief 차례만 남기고 대기, 승인 전 poller가 건드리지 않음). TestClaudeMismatchesDoNotGenerateOrDestroyWaitingRun은 본문·소유자 불일치만 보므로 인용하지 않는다. 모델+제공자 고정은 pinGroup(gateway.go:1917-1942, 호출 1862, 불일치 409는 1863)을 읽어 확인했다.
한계: 이제 읽기·once·채팅 단계도 시간 예산을 나눠 쓰므로 뒤 시도는 새 timeout 대신 남은 시간만 받고, 예산이 다 되면 budget_spent로 멈춘다. stopped 값을 모두 effect_unknown으로 읽는 사용처가 있으면 잘못 읽으며, 사용처는 점검하지 않았다. tried에는 시작 전 거절을 포함해 실제 시도만 들어간다. 시작 뒤 429로 끝난 CLI는 이제 쓰기 단계를 멈춘다. crew run 노드의 사용자 설정 callAI 재시도는 이 카드 경로 밖이라 실패 단계를 다시 돌릴 수 있다. 호출 보고에는 멈춤 표시가 없고 routed 결과에만 있으며, meeting·workflow 재시도 코드가 routed.stopped를 따르는지는 확인하지 않았다. 시작 뒤 실패한 기본·쓰기 단계는 이제 넘어가지 않으므로 대부분의 라우팅 쓰기 단계에서 대체 실행은 시작 전 거절에만 남는다. group·handoff 라우팅 경우는 시험을 추가하지 않았다. 공유 예산은 시간뿐이다. 도구·호출 횟수 공통 한도는 없고(노드 결과가 횟수를 내놓지 않음) 시도 횟수는 crew 코드가 상한을 두지 않는 후보 목록으로만 묶이므로, 카드의 공통 도구·호출·시간 한도는 일부만 충족한다. 올림 때문에 마감을 1초 미만 넘길 수 있고, decide 호출과 작업 맥락 읽기는 예산 밖이며, 시작된 시도 하나가 남은 시간을 다 쓸 수 있다. 모든 실행 경로가 덮어쓴 timeout_s를 따르는지는 코드를 읽어 확인했을 뿐 시험하지 않았다(로컬 runnode.go:302·333·353, 실행기 backend_run.go:251·316). 동시성 예약·정산은 구현하지 않았다. Gateway·meeting 동작은 바꾸지 않았고 새 시험·변이도 없다. 외부 실행기 결과는 오류와 시간만으로 판정해 시간이 없으면 쓰기 단계를 멈춘다. 시작 전 한도 거절은 지연 0ms, 시작한 실행은 최소 1ms로 보고되며 latency_ms 사용처는 점검하지 않았다. 전체 로컬 검사와 golangci-lint는 돌리지 않았다(lint는 CI). 제품 빌드·배포·병합은 하지 않았다.

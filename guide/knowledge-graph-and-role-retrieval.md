# 역할별 기억 검색과 명시적 지식 관계

역할별 검색은 `POST /v1/memory/role-search`에서 기존 검색 입력과 `role`을 받는다. 역할은 권한이 아닌 서버에 고정된 검색 용도다. 호출자의 인증·범위·원본 근거·기억 유효 기간 검사를 그대로 거친다. 호출자가 추가한 `kinds`는 아래 목록과 교집합을 취하며, 공집합은 오류로 반환한다. 태그·날짜 등 기존 조건도 유지된다.

| 프로필 | 검색하는 기억 종류 |
| --- | --- |
| researcher | semantic, episodic, user, decision, lesson |
| implementer | procedural, user, decision, lesson |
| reviewer | procedural, semantic, user, decision, lesson |

이 세 프로필은 제한된 기본 제공 분류다. 사용자 정의 역할의 의미를 추론하거나 역할마다 접근 권한을 자동 부여하지 않는다. `raw` 원문은 주입하지 않으며 기존 검색 결과 수·문자·토큰 예산을 적용한다. 프로필을 선택하는 것은 다른 사용자의 기억 접근을 허용하지 않는다.

`POST /v1/knowledge-graph/relations`는 사람 권한으로만 명시적 개체 관계를 기록한다. 입력은 `scope`, `source`, `target`, `relation`, `evidence`다. 개체는 `kind`와 불투명한 `id`로 식별하며, 근거는 승인되어 현재 유효하고 원본이 살아 있는 `memories`의 정확한 ID와 revision이어야 한다. 근거의 실제 내용과 관계가 일치한다는 판단은 관계를 작성하는 사람이 책임진다. 시스템이 모델의 추론을 검증된 사실로 자동 승격하지 않는다.

같은 근거·작성자의 동일 관계를 다시 기록해도 중복되지 않는다. 기존 관계의 근거나 작성자를 조용히 덮어쓰지 않는다. 근거 기억의 revision이 바뀌면 기존 관계를 제거하므로 다시 확인한 뒤 기록해야 한다. 근거 기억·원본의 삭제, 격리, 상태 변경은 관계와 더 이상 사용하지 않는 노드 식별자도 정리한다. 읽기 잠금이나 검색 횟수 변화로 관계를 지우지는 않는다.

`POST /v1/knowledge-graph/expand`는 `scope`, `start`, `max_depth`, `limit`을 받는다. 방향이 있는 너비 우선 탐색으로 최대 3단계, 반환 50개, 검사 200개 관계까지만 다룬다. 기본값은 1단계·20개다. 매 단계마다 근거 기억의 접근 권한과 유효성을 다시 검사하며 접근할 수 없는 관계를 거쳐 더 멀리 이동하지 않는다. 반환 직전에 트랜잭션 안에서 기억·원본의 살아 있는 상태를 다시 검사한다. 제한 때문에 더 살펴보지 않은 관계가 있으면 `truncated`를 표시한다.

결과는 관계와 근거 참조이며 신뢰할 수 없는 데이터로 취급한다. 자동 인과 추론이나 전체 대화 복사 기능이 아니다. PostgreSQL의 기존 `entities`/`relations` 테이블을 사용하며 `asserted_` 접두사로 기존 실행 근거 그래프와 구분한다. 별도 그래프 데이터베이스는 필요 없다.

검증은 역할 조건의 교집합·선별 순서, 에이전트 쓰기 거부, 범위 격리, 만료·revision 변경, 순환·분기 탐색 제한, 동시 삭제, PostgreSQL 저장·재조회·원본 직접 삭제 시 식별자 정리를 포함한다.

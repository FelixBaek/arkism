# 목록 로딩과 가상화

2026-10-21, Windows 데스크톱 UI의 현재 구현이다. API 계약과 데이터의
승인·삭제 권한은 유지하고 목록 전송·표시·새로고침을 개선했다.

| 목록 | 처음 읽기 | 다음 읽기 | 검색·분류 범위 |
|---|---|---|---|
| 기억 | 50개 | ‘더 보기’의 서버 커서 | 본문·요약·종류·저장소·상태·정렬 모두 전체 권한 범위 |
| 승인 대기·충돌 후보 | 각 50개 | 서버 커서 | 검색·종류·위험도·날짜 정렬은 전체; 유사 후보 묶음은 읽은 항목 |
| 스킬·스킬 휴지통 | 각 50개 | 서버 커서 | 검색·분류·에이전트·상태·정렬은 전체; 같은 이름 묶음은 읽은 항목 |
| 자료 | 50개 | ‘자료 더 보기’ | 문서 이름·현재 문서의 모든 목차·형식·상태·정렬은 전체 |
| 세션 | 50개 | ‘세션 더 보기’ | 선택한 기간의 제목·프로젝트·ID·에이전트·정렬은 전체 |
| 개요 큰 창의 기억·후보·세션 | 50개 | ‘더 보기’ | 전체 서버 검색·정렬; 고정 80행 잘림 제거 |

기존 GET 목록은 초기 요약 호환용으로 남긴다. 실제 관리 화면은
`POST /v1/memories/query`, `/v1/memory_candidates/query`, `/v1/skills/query`,
`/v1/knowledge/sources/query`를 쓴다. 새 서버가 필요하며 미지원·거부·실패를
빈 전체 결과로 바꾸지 않고 오류와 재시도를 표시한다. 후보 묶음·스킬 사본·
홈과 개요 요약은 여전히 읽은 항목 기준임을 화면에 명시한다.
대화 원문·과거 기억·위키 등 다른 도메인의 기존 계약은 유지한다.

## 전송과 갱신

`modules/collectionPaging.mjs`가 초기 요약 커서를 관리하고,
`modules/catalogQuery.mjs`가 기억·후보·스킬 관리 쿼리를 관리한다.
`modules/remoteCollection.mjs`는 자료·세션·개요 창의 키·메타데이터·갱신을 공유한다.
기존 `memory-pages.js` 전송기를 공유하며 서버·scope·연결 세대가 바뀐 응답은
현재 데이터에 게시하지 않는다. 잠금은 커서와 진행 중 계산을 초기화한다.
응답의 authority·항목 ID·크기·커서를 검증하고 중복 ID를 제거한다.
여러 클릭에 걸친 순환 커서도 거부한다. 실패하면 이전 항목·커서를 유지하고
‘다시 불러오기’를 제공한다. 스킬 다음 페이지의 버전 검사도 새로 수행한다.

자동 새로고침·검토 후 갱신은 실제로 열었던 페이지 수만 다시 읽는다.
항목 수로 페이지 수를 추정하지 않으므로, 비어 있거나 읽을 수 없는 스킬이
포함된 페이지도 갱신 범위에서 사라지지 않는다. 개요 창의 검토 후 갱신도
같은 경로를 사용하며 10만 개를 연속으로 읽던 별도 루프는 제거했다.
부분 갱신 실패는 이전 페이지 창을 유지한다.

`modules/visibleSync.mjs`는 읽기 계획·결과 게시·스케줄을 나눈다. 화면·연결·
데이터 객체가 바뀌거나 사용자가 편집 중이면 늦은 결과를 게시하지 않는다.
‘더 보기’가 이미 바꾼 배열을 이전 갱신으로 덮어쓰지 않는다.

## 화면과 복잡한 계산

150행을 넘긴 기억·검토·스킬·자료·세션 목록에 `modules/virtualList.mjs`를 적용한다.
화면과 위아래 여유 행만 만들고, ResizeObserver로 실제 높이를 측정한다.
Fenwick tree로 높이 합계와 스크롤 위치를 찾는다. 고정 행 높이를 강제하지
않으므로 긴 본문·창 너비·글자 크기 변화에 대응한다. 작은 목록은 기존 DOM을
유지한다. 읽은 데이터 배열은 보관하므로 이 기능이 메모리 상한을 뜻하지 않는다.

초점이 있는 행은 화면 밖으로 스크롤해도 한 행만 추가로 유지한다.
Tab/Shift+Tab·위/아래·Home/End로 생략된 행까지 이동한다. 화면 전환 시
관찰자·리스너를 해제한다. 갱신 후 행 초점, 검색창 선택 범위·입력 커서를
복원하며 늦은 요청 완료가 검색창의 초점을 ‘더 보기’로 옮기지 않는다.

후보 묶음은 닫혀 있으면 내부 행을 생성하지 않는다. 펼치면 최대 50개와
이전/다음 후보 버튼을 표시한다. 모든 후보를 개별 검토할 수 있다.
경계·조건·부정·수치·근거 표시 규칙은 기존대로 유지한다. 후보 묶기와 같은 이름
스킬 묶기를 Map으로 인덱싱해 반복 배열 복사·전체 그룹 재검색을 줄였다.

스킬 유사도는 기존 Dice/Jaccard 60% 기준과 동률 순서를 유지한다.
`modules/skillSimilarity.mjs`는 결과 상위 20개만 보관하며, 큰 목록에서는
일정 작업마다 이벤트 루프에 제어를 돌려준다. 새 목록·잠금은 이전 계산을
취소한다. 최악의 비교 횟수는 여전히 이차식이다. 대규모 전체 카탈로그를
서버에서 색인한 기능으로 바꾸었다고 주장하지 않는다.

## 서버 쿼리 계약과 비용

관리 POST 쿼리는 기본 50개, 최대 100개를 반환한다. 세션 GET은 기존 최대
500개·기본 200개를 유지하고 UI만 50개를 요청한다. 검색·필터·전체 정렬 후
페이지를 자른다. 다음 커서는 범위·사용자·역할·조건·정렬·전체 결과의 해시에
묶인다. 다른 쿼리의 커서는 400, 결과가 바뀐 커서는 409를 반환한다.
UI는 409에서 이미 열었던 페이지 창을 처음부터 다시 읽는다. 사용자 권한을
카테고리 규칙이나 로컬 환경설정으로 확대하지 않는다.

Postgres 자료·바인딩·세션 읽기는 정확한 scope와 ID 이어 읽기를 사용한다.
자료 500개, 목차 200개, 세션 20,000개라는 내부 잘림을 제거했다. 세션의
모델 동률·합산 순서도 고정해 변경 없는 데이터의 커서가 무효화되지 않게 한다.
개별 모델·도구·스킬 값은 전체를 반환한다. 기존 인증·삭제·격리·출처 확인을
거친 후 결과를 만든다. SQL 행 접근은 기존 토큰과 RLS 경계를 유지한다.

전송량만 페이지로 제한하며 서버는 전체 권한 결과를 읽고 정렬한다. 따라서
계산·메모리는 결과 크기에 비례하고 일부 정렬은 O(n log n)이다. 세부 권한과
동적 상태를 SQL COUNT로 우회하지 않는다. 요청 기한을 넘기면 실패를 반환하며
부분 결과를 전체 개수로 표시하지 않는다. 큰 운영 DB의 지연·메모리 실측은
별도 검증이 필요하다. 지속 변경되는 데이터는 커서 충돌과 재시작이 잦을 수 있다.

## 개요 › 기억 처리 창의 읽기

각 단계 창은 이미 읽은 데이터와 읽기 전용 API만 쓴다. 쓰기는 기존 승인·고치기
경로 그대로다.

| 단계 | 보여 주는 것 | 읽는 곳 |
|---|---|---|
| 불러오기 | 누가(에이전트)·어느 프로젝트에서 기억 몇 개를 받았는지, 기억마다 종류·첫 줄·고른 이유(뜻·낱말·이름·연결·고정). 점수는 ‘점수 보기’ 안 | `GET /v1/recalls`, 기억 이름은 `POST /v1/memories/query`의 `ids` |
| 사용 기록 | 처음부터 넓은 창. 기억마다 넣음·쓰임·추정·마지막 불러옴·추세(이번 주 대 그전 3주 평균), 정렬 4가지·필터 3가지. ‘‹ 작게 보기’는 단계 창 | 호스트 `memory_use` 보고, `GET /v1/memory_usage` |
| 분석 | 최근 대화·메시지 수, 후보가 나온 대화 수, 나온 후보의 종류 막대, 승인 대기·승인·중복 의심·충돌·버림 수, 버린 이유 상위 3개 | 세션 목록, 후보, `GET /v1/memory_candidates?status=rejected&created_from=7일 전` |
| 대화 저장 | 최근 대화·메시지·토큰 수, 기억·후보가 나온 대화 수, 원문 보관 중·만료·없음 수와 가장 빠른 만료. 목록·원문은 세션 기록 창 | `POST /v1/usage/sessions/archives` (세션 ≤50개, 원문 없이 상태만) |

- 기억 이름은 그리는 한 번에 모아 `ids`(≤100개)로 한 번 읽는다. `ids`를 모르는
  옛 서버는 400을 주므로 그때만 하나씩 `GET /v1/memories/{id}`로 읽는다.
- 창을 새로 열면 요약 데이터를 다시 읽고, 이름이 도착해 다시 그릴 때는 읽은 것을 쓴다.
  실패한 읽기는 그 창에서 다시 시도하지 않는다.
- 원문 보관 상태는 바이트 크기를 저장하지 않으므로 크기 대신 메시지·토큰 수를 쓴다.

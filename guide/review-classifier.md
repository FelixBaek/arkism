# 검토 순서 보조 모델

Task: none (PR #121 검토·수정)
Research: none

기억 회수는 내용 생성일 또는 유효일로 종류별 시간 감쇠를 계산한다.
메타데이터만 갱신해도 오래된 내용이 새 기억으로 취급되지 않는다.
선호·절차 등 반감기가 없는 종류는 감쇠하지 않는다.

선택적인 검토 모델은 사람이 승인·거절한 이력으로 검토 페이지 안의 순서만
바꾼다. 자동 승인·거절 권한은 없다. 기본값은 모델 없음이다.
`memoryd -train-review-classifier <모델 경로> -recall-baseline-scope w/p/u/a`로 학습하고,
`MEMORY_REVIEW_CLASSIFIER`에 경로를 지정해 로드한다.
기존 임베딩 설정과 `MEMORY_WORKER_TOKEN`의 검토·외부 전송 권한이 필요하며
제공자 비용이 발생할 수 있다. 학습도 항목별 `external:embedding` 권한을
확인하고 제공자 사용량을 기록한다. 후보 결정은 바꾸지 않지만
감사·사용량 기록은 DB에 추가한다. 복원으로 게시 차단된 DB에서는 거부한다.
임베딩 호출은 LLM용 월간 예산 예약 API와 연결되지 않아 비용 상한을 강제하지
않는다. 캐시는 반복 비용을 줄이지만 최초 전체 학습의 비용을 제한하지 않는다.
`-train-review-exclude`의 기본값은 `arkism-memory-reviewer`이다.

모델은 학습한 scope 및 임베딩 공간과 일치할 때만 사용한다. 학습 가중치는
개인 이력의 파생 데이터이므로 공개 저장소나 릴리스에 넣지 않는다.
모델 파일은 원자적으로 교체하며 읽기는 4MiB로 제한한다.
이전 scope 없는 파일은 거부하므로 다시 학습해야 한다.

새로고침 때 동일 점수를 10분간 메모리에 보관한다. 최대 4,096개 점수와
4,096개 진행 요청을 유지하며 같은 요청의 동시 호출을 합친다.
원문·벡터를 캐시에 보관하지 않는다. scope·주체·모델·내용·revision 변경은
점수를 재사용하지 않는다. 캐시 조회 전에 현재 항목별 전송 권한을 다시
확인한다. 제공자 실패 시 점수 없이 기존 순서를 반환하고 다음에 재시도한다.
전체 목록 검색을 위한 내부 스캔에서는 이 유료 보조 점수를 요청하지 않는다.

검증 기록: 기존 PR의 최종 커밋 Checks·Coverage·Sonar 성공을 확인했다.
검토 중 반복 호출, 항목별 권한, scope 격리, 실패 후 재시도, 동시 호출,
만료·상한·취소 및 파일 제한 회귀 테스트를 추가했다.
추가한 Go 코드는 아직 컴파일·실행하지 않았다. 사용자 빌드 승인 후
Windows 테스트와 최종 커밋 CI로 확인해야 하며 과거 CI 성공이 이를 대신하지 않는다.
학습 모드는 분리된 daemon 모드 구조에 연결했고 다른 모드·복구 모드와
함께 실행하지 못한다. 전체 목록 스캔은 실제로 보조 점수를 생략한다.
통합 후 소스 복잡도 검사는 기준선 증가 없이 통과했다. 이것은 타입 검사나
실행 테스트가 아니며 Windows 검증은 아직 남아 있다.

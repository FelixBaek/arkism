# SYS-04 A — lifecycle dependency and restore model

Task: `SYS-04.spec`, roadmap #152. Research: engineering synthetic lifecycle model, not a product deletion or scientific result. Design: externally supplied current metadata + exact scoped ref/revision graph, handwritten closure expectations, separate restoration/readback observations. Relation: **adapted**. Deviation: new fixture-only DTO and planner live in the original allowed `test_lifecycle.py`; no shared wire type, reducer, erasure worker, snapshot gate or product schema is changed. Why: detect stale derived material and unresolved provenance before actual storage integration.

The public candidate contains exactly the original five allowed files. `lifecycle_contract.json` is the protocol, policy and current-code inventory; `dependency_cases.json` and `restore_cases.json` contain literal input schedules and expected sets; `test_lifecycle.py` implements the pure `plan(bytes_or_dict)` and exact `validate_claim` checker plus regression tests. The planner performs no I/O except the test-only fixture/dependency loading and a bounded stdlib Python subprocess test.

## Scope and prerequisites

Fixed DYN contract SHA `952d663b76254e15a3a65ab09dcd580504bc4c2814ce4903a8883ece1ca8f0da`, baseline v1, accepted SYS-01 A fence contract and accepted SYS-03 A atomicity contract are hash-pinned and read-only. SYS-01/SYS-03 acceptance is synthetic A only. Native dynamic durable storage is not present in this work, and a proposed private implementation plan is not a live producer or implementation. Full SYS-04/B remains open. Existing product implementations are reused as **source semantics and integration boundaries**, not reimplemented or claimed exercised by these tests.

`memory_time.go` records lifecycle/status/revision/content hashes, not another body. Historical `memoryAt` requires currently authorized, non-erased canonical records and current source checks; an old hash with different current body is `content_unavailable`. Candidate correction hold leaves the existing memory active until confirmation. Current ref/status controls confirmed correction; even identical content at a higher revision requests a fresh DYN pending template, without transferring old state/evidence/cursor. The planner requests that owner operation; it does not activate or persist a state or infer accepted clock/sequence. Lower current revision is held. No inverse jump, numeric rollback, old body reconstruction or AGM guarantee is claimed.

## Input and output

All objects and fields are closed; missing and extra fields, unsupported namespace, ambiguous records, duplicate nodes, bool-as-integer, nonfinite JSON and out-of-range integer clocks/revisions fail with fixed diagnostics. All IDs are bounded fixture labels; all hashes are lowercase SHA256. The fixture namespace deliberately does not impersonate native `Ref`/DYN evidence or authorization. `current.read_authorization=confirmed`, receipts and ledger metadata are **supplied synthetic observations**, never an authentication grant.

Roots carry exact four-part scope and full collection/ID/revision/hash. A memory revision depends on source nodes. Facts carry an explicit fixture fact ID tied to a single memory revision. Other objects require dependency groups (AND within a group, alternatives across groups). Missing provenance, references, cycles or foreign-scope dependencies hold affected objects and downstream consumers. Unsupported invalidation is an explicit hold, never silent retention or deletion completion. Out-of-scope nodes remain out of scope even with identical hashes/text.

Withdraw `a` while independent `b` shares its memory revision: `a` dependents are invalidated; `b` remains when its own source is current. A composite `a+b` is invalidated. A live alternative allows a **new rebuild request**; the old artifact is still planned invalidated and cannot be reused. Whole source/revision deletion invalidates both. Fact withdrawal metadata is a synthetic model feature; a native typed fact/provenance producer and actual content reconstruction are unresolved. Existing digest erasure clears composites after member deletion, consistent with refusing to retain mixed old bytes.

`plan` returns per-object action/reason, planned invalidation/hold/rebuild sets, separate pending revision requests, restoration candidates, and per-target deletion evidence. Input state is immutable; no actual writes occur. The output always identifies the model-only scope, no publication grant, no model verification of physical erasure, zero numeric updates/inverse jumps and mandatory current publication re-fence. `keep` is only a model candidate. Old receipts are lifetime-dependent objects, not proof of a current read, model use, authorization, or successful task. A crew spool with only `{scope,trace}` and no resolved origin is explicitly held; it does not acquire guessed memory provenance. Context usage records server return, with actual use not measured.

Historical queries return `historical_only` for a matching historical revision/hash that the current record can still supply; this is not a current dynamic state or execution context. Missing/empty history is unknown, known creation after the requested date is absent, and deletion/withholding dominates history. Current source revisions are still checked for historical reads.

## Restore and evidence boundaries

Fixtures explicitly schedule reader capture, correction/deletion, worker retry and later read/publish/restore against the new current metadata. They are observations, not simulated native events. Current ledger unknown differs from a known empty ledger. Rechecks before snapshot capture are stale. An unrelated changed ledger does not invalidate unrelated exact refs, but current checks remain necessary. Current restore gate pending/unknown blocks model candidates. A canonical snapshot is not a future deletion fence; actual transaction/paused generation and `CheckRestorePublication` remain the integration owner's responsibility.

Every restore fixture compares six explicit snapshot/readback digests: state, receipt, consumption, event cursor, checkpoint and dependency index. Missing/unknown/mismatching fields prevent candidate restoration. A fresh Python process serializes/reads/recomputes one complete model plan; this is not a database crash/restart/rollback test, actual body readback or Transfiver product recovery result. Stored success alone proves neither full restore nor rollback.

Per scoped collection/ID, evidence separately reports serving blocked, derived invalidated, runtime purged, physical purge, artifacts purge, backup expiry and verification. Each is `observed_complete`, `observed_incomplete`, `unknown` or `held`; observed states require a supplied jobs receipt ref. Current product `PrivacyDeletion.State` remains distinct from queue status. Quarantine, partial/runtime failure, legal hold and backup wait cannot become one deleted bool. No authenticity or physical completeness follows from supplied metadata, even when every receipt says complete. Synthetic closure cannot verify deletion bytes/backups. `PrivacyPurgeReport`, current deletion ledger and actual jobs/fences must be connected and independently verified in B.

## Signed-time correction

Nullable timestamps remain nullable; zero is never a missing-time sentinel. History uses an explicit no-previous marker rather than `-1`, while preserving nondecreasing ordering, last-entry precedence for equal timestamps, and future-bound checks. Signed boundaries, overflow, bool/missing clocks, ordering, effective/expiry, history and restore regression checks are added. This changes parser range compatibility only; authorization, hash/scope/cfg, graph policy, six restore fields and model-only limits are unchanged.

## Current-main ordinary Eval metadata profile

`sys-lifecycle-metadata-v2` / `sys04-main-eval-roots-v1` adds a separate current-only closed metadata root profile for sources, memories, evaluations, eval_tasks, eval_runs, eval_trials, judge_calibrations at public main a389082b77cc57f45c174a561cb443a2d533e83f. Legacy v1 behavior, original fixtures, signed clocks, six restore fields and seven erasure facets remain unchanged. This is synthetic supplied metadata, not an implemented authorized native exporter.

New input has `metadata_profile` and `root_metadata`. The profile binds exact source version, ordered collection list, external expected scoped full roots and an extraction SHA. Every exact root must occur in graph and extraction; required Sources/Target/Relations/Evaluation refs and trial task/run relations are a single AND group. Unsupported/missing/duplicate extraction, foreign-scope joins and silently dropped/alternative edges reject. Missing current observations, stale or conflicting pinned roots hold. Known deletion invalidates. Cycles hold. Source-free ordinary current roots are permitted as observed metadata anchors; downstream objects still require provenance. The new profile does not support historical query/fact withdrawal; the unchanged legacy profile retains those model features.

Extraction SHA256 uses `sys04-main-eval-roots-v1:extraction\0` plus sorted compact newline UTF8 JSON of root_metadata. Coverage SHA256 uses `sys04-main-eval-roots-v1\0` plus the same representation of id/source_commit/collections/expected_roots/extraction_sha256. Array order is preserved. V2 input digest has its own `sys-lifecycle-metadata-v2\0` domain. The separate snapshot/readback coverage hashes must both match for restore; all six original field digests equal cannot hide incomplete declared roots/edges. These supplied hashes do not authenticate an actual producer or complete DB/backup coverage.

Only memory approval controls memory current eligibility. Ordinary live/calibrated Eval metadata never establishes learning qualification; output says not_established. Removal maps only to rejected/current-revision observations: raw Note/By are not input fields and it never proves fact/physical deletion. Native canonical nil-ref guards and native code remain untouched. Actual native extraction, database readback, dependency-store invalidation, publication fences and B integration remain pending.

V2 external Scope/Ref string rules exactly follow a389 validScope/scopeName/validRunLabel on UTF8 JSON strings: workspace/project bytes1..255 with no dot/dotdot, slash/backslash or Cc; user/agent bytes0..255 only (including empty/Cc/Cf/path-like values). Ref IDs bytes1..256, unchanged under Go Unicode TrimSpace and no Cc. Cf is allowed. Internal graph IDs keep fixture-label rules, v1 rules remain unchanged. No normalization or alias is performed; invalid Unicode scalar strings reject rather than rewrite.

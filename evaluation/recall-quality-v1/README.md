# 공개 합성 기억 검색 평가셋 v1

ST-811 / ST-815, FR-020 / FR-021의 개발 평가 자료다. 운영 기억·사용자 기록을 사용하지 않았다. 한국어 기억 36개와 질문 144개를 모델 검색 결과를 보지 않고 작성했다. 라벨은 에이전트가 작성하고 별도 에이전트가 모델 결과 없이 전수 검토한 잠정 판단이며, 사람의 품질 정책 승인이나 실제 사용자 만족도의 증거가 아니다.

## 범위와 분할

`dataset.json`은 기억 36개, 관련 질문 72개, 명확한 무관 질문 60개, 모호한 질문 12개를 담는다. 각 기억에는 관련 질문 2개와 무관 또는 모호 질문 2개를 연결해 작성했지만, 평가는 모든 기억 36개를 공통 검색 대상으로 삼는다. 질문 ID나 작성상 연결 관계를 검색·재판별에 제공하지 않는다.

조정용 `calibration`과 검증용 `holdout`은 각각 기억 주제 18개와 질문 72개로 나뉜다. 같은 기억의 표현 변경 질문이 양쪽에 들어가지 않는다. 두 분할은 일정·문서·개발 등 넓은 분야를 공유할 수 있지만, 구체적인 기억 정책은 공유하지 않는다. 범용적인 새 분야 전체로의 일반화를 측정하는 분할은 아니다.

기존 소규모 평가의 회귀검사·배포·백업·개인정보·보고·기억 승인 문장을 재사용하지 않았다. 회계, 도서 대여, 행사 간식, 장비 배치, 외부 요청, 단위, 번역, 인쇄, 실험 시료, 계약, 물류, 접근성, 결제, 구독, 센서 등으로 범위를 넓혔다.

## JSON 계약

- `documents`: `id`, `split`, `topic`, `text`, `summary`, `kind`, `provenance`.
- `queries`: `id`, `split`, `category`, `text`, `relevant`(문서 ID 배열), `label_status`.
- `relevant=[]`는 이 corpus에서 직접 도움이 되는 기억이 없다는 뜻이다. 같은 낱말이나 넓은 주제만 겹치는 것으로 정답 처리하지 않는다.
- `label_status=independent_agent_reviewed`는 별도 에이전트가 독립 검토한 명확한 잠정 라벨이다. 사람의 승인을 뜻하지 않는다. 이 상태를 이진 평가에 포함한다.
- `label_status=ambiguous`는 단독 질문에서 지시 대상이나 필요한 상황을 알 수 없다는 뜻이다. `relevant=[]`를 무조건 부정 정답으로 해석하면 안 된다. 주 관련성 지표에서 제외하고 출력·보류 동작을 별도로 보고한다.
- 모호한 질문의 `plausible_if_context_supplied`는 누락된 상황이 제공될 경우 가능한 문서의 비완전 참고 목록이다. 현재 질문의 정답이나 채점 기준이 아니며 모델 입력에 제공하지 않는다.
- 모든 `summary`는 빈 문자열이다. 임베딩할 원본은 실제 `recordContent` 계약대로 **`text + "\n" + summary`**다. 끝의 개행을 제거하지 않는다. 질의 임베딩의 지시문·모델·revision·space는 실행 결과에 별도로 기록한다.
- 재판별에는 질의의 `text`와 후보의 `text`/`summary`만 제공한다. `relevant`, 분할, category, ID의 주제명, 모호성 주석 등 평가 라벨 정보는 제공하지 않는다.

`category`는 주된 언어적 특징이며 서로 완전히 배타적인 언어 현상이 아니다. `relevant`는 직접적인 요청, `paraphrase`는 표현 변경, `synonym`은 대체 용어, `negation`은 금지·부정 포함 요청, `correction`은 잘못 제안된 행동의 정정을 묻는 요청이다. `near_negative`는 겹치는 낱말이나 인접 분야를 쓰지만 기억의 정책으로 답할 수 없는 질문, `unrelated`는 일반 무관 질문, `ambiguity`는 지시 대상이 빠진 질문이다.

## 평가 절차

1. 독립 검토자는 모델 결과를 보기 전에 모든 관련 문서 라벨과 무관·모호 구분을 검토한다. 다른 기억도 실제로 질문에 도움이 된다면 `relevant`에 추가한다. 분할을 넘는 관련 문서가 발견되면 주제 분할도 함께 수정한다.
2. 검토와 수정은 최초 성능 측정 전에 끝내고 `freeze.json`에 dataset/README SHA-256과 상태를 기록한다. 모델 결과를 본 뒤 이 버전의 질문이나 라벨을 바꾸지 않는다. 이후 발견한 라벨 문제는 별도 이슈/다음 버전에 남긴다.
3. 후보 수, 재판별 정책, 임계값, 프롬프트와 모델 선택은 calibration 질문만 사용한다. holdout은 선택을 고정한 뒤 최종 비교에 한 번 공개한다. 이미 본 holdout 결과를 바탕으로 조정했다면 이를 새로운 검증 결과처럼 보고하지 않는다.
4. 비교 실행은 동일 corpus·질문·권한·host budget을 사용한다. 기존 검색, 후보 확장만 적용, 후보 확장과 재판별 적용을 구분하면 재판별의 효과와 손실을 확인할 수 있다. 외부 제공자 실패 시 동작도 별도로 확인한다.
5. 재현을 위해 코드 revision, 데이터 해시, 임베딩/재판별 모델 revision, 입력 형식, 후보 수, 거리·재판별 기준, 실제 반환 경로, 실행 환경을 결과와 함께 기록한다.

## 함께 보고할 수치

- **정답 회수율**: 관련 질문 중 적어도 하나의 라벨 문서를 최종 반환한 질문 수 / 관련 질문 수. 다중 정답이 생기면 문서 단위 recall도 함께 보고한다.
- **반환 정밀도와 정답 외 문서 수**: 최종 반환 문서 가운데 `relevant`에 있는 문서의 비율과 없는 문서의 개수. 질문당 중복 ID는 한 번만 센다.
- **무관 질문 오탐률**: 명확한 무관 질문 중 하나라도 반환한 질문 비율. near-negative와 일반 무관을 분리한다.
- **후보 단계 회수율**: 재판별 전의 후보에 정답이 들어온 비율. 후보 누락과 재판별의 잘못된 탈락을 구분한다.
- **모호성**: 12개를 위 지표의 분모에서 빼고 기억 반환/보류 수를 별도 기록한다. 문맥이 없는 질문의 유일 정답을 만들어내지 않는다.
- **응답 시간**: 전체 검색 및 재판별 추가 시간의 p50/p95와 실패·timeout 수. 준비 실행, cold/warm 상태, 동시성, 반복 횟수를 명시한다. 실패한 요청을 지연 통계에서 조용히 제외하지 않는다.
- calibration/holdout, category별 결과와 전체 결과를 모두 남긴다. 적합한 결과를 더 찾았더라도 오탐·지연이 늘 수 있으므로 개선을 미리 단정하지 않는다.

## 한계

합성 정책과 질문은 실제 운영 분포나 실제 사용자 표현의 다양성을 대표하지 않는다. 한 사람이 아닌 에이전트가 관련·무관 문장을 함께 작성했으므로 문체 단서가 생길 수 있다. 각 기억을 겨냥한 관련 질문이 두 개뿐이어서 긴 대화, 복수 기억 조합, 충돌하는 최신/이전 규칙, 권한·삭제 경계, 다국어, 장문, 적대적 문서 입력은 이 자료의 성능 수치로 검증되지 않는다. 권한·생존·원문 검증은 기존 별도 회귀를 계속 통과해야 한다.

## 독립 검토 기록

2026-10-18 별도 에이전트 `memory_capture`가 모델 출력이나 점수를 보지 않고 기억 36개·질문 144개를 전수 검토했다. 관련 72개와 명확한 무관 60개에서 추가 정답 누락이나 잘못된 이진 라벨을 발견하지 않았고, 모호한 12개를 별도로 두는 것이 타당하다고 판단했다. 두 질문의 주된 표현 범주를 동의어로 명확히 했고, 모호 질문의 참고 후보가 완전한 정답 목록으로 오해되지 않도록 주석을 보완했다. 이 검토는 사람의 품질 승인을 대신하지 않는다.
